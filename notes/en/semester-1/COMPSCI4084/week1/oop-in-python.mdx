## Overview
- **Goal**: Understand classes, objects, encapsulation, inheritance, and composition, and be able to model problems and constraints using an appropriate object model.
- **Scope**: Covers class definition and instantiation, constructors and methods, attributes and encapsulation, inheritance and method overriding, composition, common dunder methods, and simple data classes.

## Learning Objectives
1. Define classes and constructors, create objects, and call instance/class methods.
2. Correctly use attributes and encapsulation, understanding single/double underscores and name mangling.
3. Master the trade-offs between inheritance/overriding/`super()` and composition, and be able to implement `__str__`/`__repr__`/`__eq__`.

## Key Concepts

### 1. Classes, Instances, and Constructors
```python
class Account:
    def __init__(self, owner: str, balance: float = 0.0):
        self.owner = owner
        self.balance = balance
    def deposit(self, amount: float) -> None:
        self.balance += amount
    def __str__(self) -> str:
        return f"Account({self.owner}, balance={self.balance:.2f})"

acc = Account("Alice", 100)
acc.deposit(25)
print(acc)  # Account(Alice, balance=125.00)
```
- **Key Points**: `__init__` initializes the instance's state. The first parameter of an instance method is conventionally named `self`.

### 2. Attributes, Encapsulation, and Name Mangling
```python
class SafeBox:
    def __init__(self, password: str):
        self._hint = "4 digits"          # "Protected" attribute by convention
        self.__password = password        # Triggers name mangling → _SafeBox__password
    def check(self, guess: str) -> bool:
        return guess == self.__password

box = SafeBox("1234")
print(box._hint)
# This is not recommended, but demonstrates the effect of name mangling:
print(box._SafeBox__password)
```
- **Key Points**: A single underscore is a convention. A double underscore rewrites the attribute name to reduce accidental access from subclasses or external code.
- You can use `@property` to expose read-only or computed attributes and control invariants.

### 3. Inheritance and Method Overriding (Polymorphism)
```python
class Animal:
    def speak(self) -> str:
        return "..."
class Dog(Animal):
    def speak(self) -> str:  # Override
        return "woof"
class Cat(Animal):
    def speak(self) -> str:
        return "meow"

def chorus(pets: list[Animal]) -> None:
    for p in pets:
        print(p.speak())

chorus([Dog(), Cat()])  # Polymorphic call
```
- **Key Points**: Subclasses can override parent class methods. Use `super().__init__()` when necessary to initialize the parent part of the object.

---

### 4. Composition Over Inheritance
```python
class Engine:
    def start(self) -> str:
        return "engine on"
class Car:
    def __init__(self, engine: Engine):
        self.engine = engine
    def drive(self) -> str:
        return self.engine.start() + ", driving"

print(Car(Engine()).drive())
```
- **Key Points**: Use composition when a "has-a" relationship is more appropriate than an "is-a" relationship. It reduces coupling and improves reusability.

### 5. Common Dunder Methods: `__str__`/`__repr__`/`__eq__`
```python
class Point:
    def __init__(self, x: int, y: int):
        self.x, self.y = x, y
    def __repr__(self) -> str:  # For developers, should be reproducible
        return f"Point(x={self.x}, y={self.y})"
    def __str__(self) -> str:   # For users
        return f"({self.x}, {self.y})"
    def __eq__(self, other: object) -> bool:
        if not isinstance(other, Point):
            return NotImplemented
        return (self.x, self.y) == (other.x, other.y)

print(Point(1,2) == Point(1,2))  # True (value equality)
```
- **Key Points**: `__repr__` should be as "reproducible" as possible. `__eq__` defines value semantics; avoid using `is` for value comparison.

### 6. Dataclasses and Immutable Objects
```python
from dataclasses import dataclass

@dataclass(frozen=True)
class User:
    name: str
    email: str

u = User("Alice", "a@example.com")
print(u)           # User(name='Alice', email='a@example.com')
# u.name = "Bob"   # This will raise an error: frozen dataclasses are immutable
```
- **Key Points**: Dataclasses automatically generate `__init__`, `__repr__`, `__eq__`, etc. `frozen=True` helps in creating immutable objects.

## Best Practices
- **Single Responsibility**: A class should focus on one abstraction. Methods should be short and have descriptive names.
- **Composition over Inheritance**: Prefer composition; use inheritance only for stable "is-a" hierarchies.
- **Avoid Exposing Mutable Internal State**: Use properties or return copies.
- **Implement `__repr__`** for developer-friendly debugging and `__eq__` for value semantics as needed.
- **Use double underscores for privacy sparingly**, as it can increase the cost of testing and extension.
