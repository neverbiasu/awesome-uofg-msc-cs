# Using Git and GitHub

## Overview
- **Goal**: Complete the minimal workflow from local development to version control and remote collaboration. Master branching, merging, conflict resolution, and ignore rules.
- **Applicable for**: This course's tAPP/Lab assignments and future project collaborations.

## Key Concepts (Quick Glance)
1) **Initial Setup**: Configure `user.name` and `user.email`. It's recommended to set the default branch to `main`.
2) **Local Workflow**: `git init/clone` → `add` → `commit` → `log/status`.
3) **Remote Collaboration**: `git remote add` (SSH recommended); `git push/pull` and setting an upstream with `-u`.
4) **Branching & Merging**: `git branch/switch/merge`; understand fast-forward merges and conflict handling.
5) **Commit Message Style**: A single summary line (`<=` 50 chars, imperative mood), followed by a detailed explanation if necessary.
6) **Ignore Rules**: `.gitignore` only ignores untracked files. Tracked files must first be removed from the index with `git rm --cached`.

## Basic Workflow (From Scratch to Remote)

### 1. Installation & Configuration (One-time)
```bash
# Recommended for macOS:
brew install git
# Basic identity configuration (global)
git config --global user.name "Your Name"
git config --global user.email "your.email@example.com"
# Set default branch name to main (for new repositories)
git config --global init.defaultBranch main
```

### 2. Create or Clone
```bash
# Create a new directory and initialize
mkdir demo && cd demo
git init  # Will use 'main' as the default branch if configured above
# Or: Clone from a remote repository (SSH recommended)
# Copy the SSH address from GitHub, e.g., git@github.com:org/repo.git
git clone git@github.com:org/repo.git
```

### 3. Modify, Stage, Commit
```bash
echo "hello" > README.md
git status              # Check changes
git add README.md       # Stage the file
git commit -m "init: add README"  # Commit
```

### 4. Connect to Remote & Push
```bash
# If you initialized a local repository, add the remote first
git remote add origin git@github.com:org/repo.git
# First push and set the upstream branch (-u)
git push -u origin main
# Subsequent pushes can be simplified to:
git push
```

### 5. Pull Updates
```bash
# Fetch and merge from the remote 'main' branch
git pull --ff-only origin main
```

## Branching & Merging
```bash
# Create and switch to a new branch 'feature/login'
git switch -c feature/login
# Alternative: git checkout -b feature/login
# After making some commits, switch back to main and merge
git switch main
# Alternative: git checkout main
git merge feature/login   # Aim for small commits and frequent merges
# Delete the merged branch
git branch -d feature/login
```
- **Recommendation**: Create branches based on features (e.g., `feature/...`, `fix/...`).
- **Merge Strategy**: Prefer fast-forward merges. Consider `rebase` only for maintaining a clean history, as agreed upon by the team.

## Commit Message Style (Recommended)
- **Structure**:
  - Summary line (`<=` 50 chars, imperative mood): e.g., `feat: add login form`.
  - Blank line.
  - Detailed explanation (optional): motivation, changes, compatibility impact.
- Group related changes into a single commit; avoid mixing unrelated files.

## .gitignore (Common Snippets)
```text
# macOS
.DS_Store
# Node
node_modules/
# Python
__pycache__/
*.pyc
.venv/
# IDE / Editor
.vscode/
.idea/
```
> Files already tracked by Git will not be automatically ignored by adding them to `.gitignore`. You must first run `git rm --cached <path>` and then commit.

## Conflict Resolution (Workflow)
1) When a conflict occurs during a merge or pull, use `git status` to see the conflicted files.
2) Open the file and manually merge the changes based on the markers:
```
Your local changes
```
3) After editing and saving, mark the conflict as resolved with `git add <conflicted_file>`.
4) Complete the merge with `git commit`. If the conflict was triggered by `git pull`, this commit finalizes the pull.

## Best Practices
- **Push requires setting upstream**: Use `git push -u origin main` for the first push, then `git push` is sufficient.
- **Remote default branch is `master`**: You can change it to `main` in GitHub repository settings. Locally, run `git branch -m master main && git fetch origin && git branch -u origin/main main`.
- **Frequent password prompts with HTTPS**: Switch to SSH (generate a key with `ssh-keygen -t ed25519` and add it to GitHub).
- **Messy merge history**: Commit small, pull often, and merge promptly. Use `git log --oneline --graph` to help visualize the history if needed.
