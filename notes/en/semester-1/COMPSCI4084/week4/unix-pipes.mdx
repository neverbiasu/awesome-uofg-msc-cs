## Overview
- **Goal**: To master the concept of Unix pipes (`|`) for composing simple, single-purpose commands into complex data processing pipelines.
- **Scope**: Covers the definition of pipes, standard streams, and practical examples of command chaining.

## Learning Objectives
1. **Understand** the concept of standard streams: `stdin`, `stdout`, and `stderr`.
2. **Master** the use of the pipe operator (`|`) to connect the `stdout` of one command to the `stdin` of another.
3. **Be able to** construct simple command pipelines to filter, sort, and count data.

### 1. Standard Streams
- **Motivation**: To understand how programs communicate, you must first understand their standard input and output channels.
- **Core Concepts**:
  - **Standard Input (`stdin`)**: The default channel where a program receives its input, typically from the keyboard.
  - **Standard Output (`stdout`)**: The default channel where a program sends its normal output, typically to the screen.
  - **Standard Error (`stderr`)**: A separate channel for sending error messages, also typically to the screen.
- **Why separate `stdout` and `stderr`?**: This allows you to redirect normal output to a file while still seeing error messages on the screen, preventing errors from corrupting your output data.
- **Summary**: Every command-line program has three standard streams (`stdin`, `stdout`, `stderr`) that handle its input, output, and errors.

---

### 2. The Pipe Operator (`|`)
- **Motivation**: Pipes allow you to build sophisticated workflows without creating temporary files, embodying the Unix philosophy of "small tools working together."
- **Core Concept**: The pipe operator `|` takes the `stdout` of the command on its left and uses it as the `stdin` for the command on its right.
- **Syntax**: `command1 | command2 | command3`
- **How it works**: The shell creates a pipeline where data flows from left to right. The commands in the pipeline run concurrently, with the operating system managing the data flow between them.
- **Example: Counting files in a directory**
  ```bash
  # ls -l lists files (one per line in its raw output)
  # wc -l counts the number of lines
  ls -l | wc -l
  ```
  In this example, the output of `ls -l` is "piped" into `wc -l`, which counts the lines, effectively counting the files.
- **Example: Finding a specific process**
  ```bash
  # ps aux lists all running processes
  # grep searches for lines containing "nginx"
  ps aux | grep nginx
  ```
  This pipeline finds and displays only the lines from the process list that are related to "nginx".
- **Notes/Best Practices**:
  - Pipes are for connecting `stdout` to `stdin`. They do not, by default, redirect `stderr`.
  - Break down complex problems into a series of simple transformations that can be chained together with pipes.
- **Summary**: The pipe is a fundamental mechanism for command composition in Unix, enabling elegant and efficient data processing directly on the command line.

## Best Practices
- **Start simple**: Begin with a single command, check its output, and then gradually add more commands to the pipeline.
- **Use `less` for inspection**: When a command produces a lot of output, pipe it to `less` to view it page by page (e.g., `ls -lR | less`).
- **Think in terms of filters**: View commands like `grep` (select lines), `sort` (order lines), `uniq` (remove duplicate lines), and `awk` (transform columns) as filters in your data pipeline.
