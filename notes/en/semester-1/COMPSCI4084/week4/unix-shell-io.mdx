## Overview
- **Goal**: To gain control over where a program's input comes from and where its output goes, and to understand basic shell concepts like variables and quoting.
- **Scope**: Covers I/O redirection (`>`, `>>`, `<`), standard streams, shell variables, and metacharacters.

## Learning Objectives
1. **Master** I/O redirection to save command output to files or read input from files.
2. **Understand** the difference between `>` (overwrite) and `>>` (append).
3. **Be able to** define and use shell variables.
4. **Recognize** shell metacharacters and understand how quoting (`'`, `"`, `\`) affects their interpretation.

### 1. I/O Redirection
- **Motivation**: While pipes are for connecting commands, redirection is for connecting commands to files.
- **Core Concepts**:
  - **Redirecting Standard Output (`>`)**: Sends the `stdout` of a command to a file, overwriting the file if it exists.
    - `ls -l > file_list.txt`
  - **Appending Standard Output (`>>`)**: Appends the `stdout` of a command to a file, creating it if it doesn't exist.
    - `echo "New log entry" >> application.log`
  - **Redirecting Standard Input (`<`)**: Takes input for a command from a file instead of the keyboard.
    - `sort < unsorted_names.txt`
  - **Redirecting Standard Error**: Use `2>` to redirect `stderr`. This is useful for capturing error messages.
    - `find / -name "secret" > results.txt 2> errors.log`
- **Summary**: Redirection gives you precise control over the flow of data between programs and files.

### 2. Shell Variables and Quoting
- **Motivation**: Shells are programming environments. Variables and quoting are fundamental to writing scripts and managing complex commands.
- **Core Concepts**:
  - **Shell Variables**: Store data. By convention, variable names are in uppercase.
    - **Definition**: `MY_VAR="Hello World"` (no spaces around `=`).
    - **Reference**: `$MY_VAR`.
  - **Metacharacters**: Characters with special meaning to the shell, such as `*`, `?`, `$`, `|`, `>`, `<`.
  - **Quoting**: Controls how the shell interprets metacharacters.
    - **Double Quotes (`"`)**: Weak quoting. Allows variable substitution (`$VAR`) and command substitution (`` `command` ``), but prevents word splitting and globbing (`*`).
      - `echo "$MY_VAR"` -> `Hello World`
    - **Single Quotes (`'`)**: Strong quoting. Disables all special meanings. Everything is treated as a literal string.
      - `echo '$MY_VAR'` -> `$MY_VAR`
    - **Backslash (`\`)**: Escapes a single character, removing its special meaning.
      - `echo "The price is \$100"` -> `The price is $100`
- **Example**:
  ```bash
  GREETING="Hello"
  TARGET="World"

  # Double quotes allow variable expansion
  echo "$GREETING, $TARGET!" # Output: Hello, World!

  # Single quotes treat everything literally
  echo '$GREETING, $TARGET!' # Output: $GREETING, $TARGET!
  ```
- **Summary**: Understanding variables and quoting is essential for moving from simple commands to powerful shell scripting.

## Best Practices
- **Always quote variables**: When referencing variables, enclose them in double quotes (`"$MY_VAR"`) to prevent unexpected behavior from spaces or special characters in the variable's value.
- **Use `>` for new files, `>>` for logs**: Use `>` when you want a fresh start and `>>` when you want to add to existing data.
- **Prefer single quotes by default**: If you don't need variable or command substitution, use single quotes to avoid accidental interpretations by the shell.
