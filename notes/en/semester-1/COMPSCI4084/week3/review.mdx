## Module: NumPy Library
> Module Reference: [NumPy](./numpy.mdx) (Reference Material: [NumPy Library (slides, MD)](../../../../materials/semester-1/COMPSCI4084-programming-systems/lectures/Numpy_Library.md))

| No. | Knowledge Point | Key Takeaway | Importance |
|---|---|---|---|
| 1 | NumPy array constructor selection | Choose `array/zeros/ones/arange/linspace` to construct data with the target dtype and shape. | ⭐⭐☆ |
| 2 | Random number generation and seed control | Use `rand`/`randint`/`normal` and set a random seed to reproduce experiments. | ⭐⭐☆ |
| 3 | Difference between views and copies | Distinguish between a slice (view) and fancy indexing (copy) to predict if modifications affect the original array. | ⭐⭐⭐ |
| 4 | Broadcasting and ufunc operations | Check shape compatibility and use broadcasting/ufuncs instead of explicit loops. | ⭐⭐⭐ |
| 5 | Semantics of matrix multiplication operators | Understand the difference between `*` and `@` and check the input/output dimensions for matrix multiplication. | ⭐⭐☆ |
| 6 | Array shape manipulation | Proficiently use `transpose/reshape/vstack/hsplit` to manage dimensions. | ⭐⭐☆ |
| 7 | Array persistence strategies | Choose `save/load` or `savetxt/loadtxt` to save and load arrays based on data size. | ⭐⭐☆ |

**Additional Thoughts:**
- Fancy indexing returns a copy. For Lab4 Task7 on stacking/splitting, pay attention to the returned object's form.
- Assessment questions often combine broadcasting and mask filtering. Be sure to test boundary cases (empty arrays or arrays with NaN).

## Module: Pandas Data Manipulation
> Module Reference: [Pandas Manipulation](./pandas-manipulation.mdx) (Reference Material: [Pandas - Data Manipulation (slides, MD)](../../../../materials/semester-1/COMPSCI4084-programming-systems/lectures/Data_Manipulation.md))

| No. | Knowledge Point | Key Takeaway | Importance |
|---|---|---|---|
| 1 | Data integration method selection | Choose between `merge`, `join`, `concat`, `combine_first` based on the scenario and explain the differences. | ⭐⭐⭐ |
| 2 | Index-based merging strategies | Use `set_index` or `left_index/right_index=True` to perform merges at the index level. | ⭐⭐⭐ |
| 3 | Hierarchical index design with concat | Use `keys`/`axis` in `concat` to build a traceable hierarchical index. | ⭐⭐☆ |
| 4 | Long-to-wide table transformation | Use `pivot/pivot_table/stack/unstack` to switch between long and wide table formats. | ⭐⭐⭐ |
| 5 | GroupBy aggregation and reuse | Master the combined use of `agg/sum/mean/count` and `transform`. | ⭐⭐⭐ |
| 6 | Label mapping and renaming techniques | Use `map`, `replace`, `rename` to unify labels or map numerical values. | ⭐⭐☆ |
| 7 | Duplicate and missing data cleaning workflow | Use `duplicated/drop_duplicates/drop/dropna` to clean duplicate records and redundant columns. | ⭐⭐☆ |

**Additional Thoughts:**
- `merge` defaults to an inner join. If the problem doesn't specify, you need to determine whether a union or intersection is needed to avoid a sudden increase in data volume.
- Assessments often provide duplicate rows or incorrect labels. Remember to diagnose with `duplicated()` first before deciding on a retention strategy.

## Module: Custom Python Packages
> Module Reference: [Custom Packages](./custom-package.mdx) (Reference Material: [Python - Creating a Custom Package (slides, MD)](../../../../materials/semester-1/COMPSCI4084-programming-systems/lectures/Introduction_to_Python_Package.md))

| No. | Knowledge Point | Key Takeaway | Importance |
|---|---|---|---|
| 1 | Package directory structure planning | Set up a package directory with `__init__.py` and explain the responsibilities of each module. | ⭐⭐☆ |
| 2 | Top-level API exposure strategy | Expose public APIs or configure `__all__` in `__init__.py`. | ⭐⭐☆ |
| 3 | Module import path management | Choose appropriate relative or absolute imports within the package to avoid circular references. | ⭐⭐☆ |
| 4 | Responsibility separation and modularization | Split I/O, cleaning, and visualization into separate modules with a single responsibility. | ⭐⭐☆ |
| 5 | Local development workflow for packages | Use `pip install -e .` or `python -m package.module` for local debugging. | ⭐⭐☆ |

**Additional Thoughts:**
- Avoid executing time-consuming logic in `__init__`, as it will slow down script startup when the package is imported.
- The Lab4 package exercise requires consistent directory naming and import paths. Be sure to verify in a clean environment before submission.

## Module: Date and Missing Data Handling
> Module Reference: [Date & Missing Data](./date-missing-data.mdx) (Reference Material: [More Data Manipulation - date format and missing data (slides, MD)](../../../../materials/semester-1/COMPSCI4084-programming-systems/lectures/More_Data_Manipulation_-_date_format_and_missing_data.md))

| No. | Knowledge Point | Key Takeaway | Importance |
|---|---|---|---|
| 1 | Date parsing parameter configuration | Use `parse_dates` and `dayfirst=True` to parse various date formats into `datetime`. | ⭐⭐⭐ |
| 2 | Date feature derivation | Preserve the original date column and extract periodic fields like `dt.to_period('M')/dt.year/dt.month`. | ⭐⭐☆ |
| 3 | Time-based indexing and slicing | Use `set_index('Date')`, time slicing, and resampling to locate time windows. | ⭐⭐☆ |
| 4 | Combined methods for handling missing values | Flexibly use `isnull/notnull/dropna/fillna/interpolate` to distinguish between deletion and filling strategies. | ⭐⭐⭐ |
| 5 | Filling strategy selection | Choose filling values like mean/median/constant based on column type and document the strategy. | ⭐⭐☆ |

**Additional Thoughts:**
- Parsing failures often stem from mixed formats. If necessary, clean the original strings before `parse_dates`.
- Assessments often test the impact of filling missing values on the mean. It's advisable to compare the before and after differences.
