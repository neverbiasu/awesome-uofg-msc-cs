## Overview
- This document is a quick-start guide to PyTorch, covering installation, Tensors and common operations, the `autograd` mechanism, defining models with `nn.Module`, common loss functions and optimizers, the standard training loop, and practical tips for moving models/data between CPU and GPU.
- The goal is to enable you to quickly build a minimal trainable model and understand each step of the training process.

## Learning Objectives
1. Install and verify a PyTorch environment.
2. Understand and operate on PyTorch `Tensors` (creation, indexing, shape transformation, device moving).
3. Master the basic usage of `autograd` for automatic differentiation (`requires_grad`, `backward()`).
4. Be able to define a feed-forward network using `nn.Module` and inspect its parameters.
5. Use appropriate loss functions and optimizers to perform parameter updates.
6. Implement a standard training loop (forward → loss → backward → step) and run it on both CPU and GPU.

## Key Concepts

### 1. PyTorch Introduction and Installation

#### Motivation
- A deep learning library that supports dynamic computation graphs (eager execution), is tightly integrated with Python, and is widely used in both research and production.

#### Core Concepts
- PyTorch is a tensor-based deep learning library that provides automatic differentiation (`autograd`), neural network modules (`torch.nn`), and optimizers (`torch.optim`).
- Common installation methods: `conda` (recommended for Anaconda environments) or `pip`.

#### Use Cases/Modes
- Research experiments, rapid prototyping, model training/fine-tuning, and production inference (with TorchScript/ONNX).

#### Example (Installation Verification)

```python
# Verify installation in a Python REPL
import torch
print(torch.__version__)
print('CUDA available: ', torch.cuda.is_available())
```

#### Notes/Best Practices
- Installing in a Conda environment avoids conflicts with system dependencies. If GPU support is needed, follow the official guide to select a matching CUDA version.
- In shared projects, lock dependency versions using `requirements.txt` or `environment.yml`.

#### Summary
First, confirm that PyTorch is correctly installed and can be imported before proceeding to learn about tensors and model building.

### 2. Tensors and Basic Operations

#### Motivation
- Tensors are the fundamental unit of all computation. Mastering tensor creation, indexing, and shape transformation is the foundation for subsequent model implementation.

#### Core Concepts
- `torch.tensor`, `torch.zeros`, `torch.ones`, `torch.arange`, `torch.linspace` are used to create tensors.
- Tensors support N-dimensions, broadcasting, shape transformations (`reshape` / `view`), and concatenation (`cat` / `stack`).
- Tensors can be placed on different devices (CPU/GPU) and moved between them using `.to(device)` or `.cuda()` / `.cpu()`.

#### Use Cases/Modes
- Data preparation, model input, parameter representation, and interoperability with NumPy (`tensor.numpy()` and `torch.from_numpy()`).

#### Example

```python
import torch

# Create tensors
x = torch.linspace(-10, 10, steps=100)   # A linearly spaced sequence
A = torch.tensor([[1.0, 2.0], [3.0, 4.0]])
zeros = torch.zeros(3, 4)

# Basic operations
y = x * 2 + 1
B = A.t()  # Transpose

# Shape transformation
z = torch.arange(6)
z = z.reshape(2, 3)  # or z.view(2, 3)

# Create/move tensors to GPU (if available)
device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
A = A.to(device)

# Interoperability with NumPy
import numpy as np
arr = np.arange(5)
t = torch.from_numpy(arr)
print(t)
```

#### Notes/Best Practices
- When training on a GPU, ensure that model parameters and inputs are on the same device to avoid device mismatch errors.
- Avoid unnecessary device copies (frequent use of `.cpu()` / `.cuda()` can impact performance).

#### Summary
Tensor operations are central to using PyTorch. Familiarity with common creation and transformation APIs will allow you to implement models and data pipelines faster.

### 3. Automatic Differentiation (`autograd`) and Gradients

#### Motivation
- Training a neural network requires computing the gradient of the loss with respect to its parameters. `autograd` automatically builds a computation graph and performs backpropagation, reducing errors from manual differentiation.

#### Core Concepts
- `requires_grad=True` makes a tensor track its operations during the forward pass for backpropagation.
- `loss.backward()` backpropagates through the computation graph and accumulates gradients into the `.grad` attribute of leaf tensors.
- Use `torch.no_grad()` or `with torch.no_grad():` to disable gradient tracking during inference to save memory.

#### Use Cases/Modes
- Enable gradients during model training; disable them during evaluation/inference.

#### Example

```python
import torch

# Simple scalar autograd
x = torch.tensor(2.0, requires_grad=True)
y = x ** 2 + 3 * x

# Backpropagation
y.backward()  # dy/dx = 2*x + 3
print(x.grad)  # Output: tensor(7.)

# Disable gradient computation (for inference)
with torch.no_grad():
    y2 = x * 2
```

#### Notes/Best Practices
- Before each `backward()` call, you typically need to call `optimizer.zero_grad()` to clear gradients from the previous step, otherwise they will accumulate.
- For complex training strategies (like multiple backward passes or gradient clipping), carefully manage the computation graph and the `retain_graph` parameter.

#### Summary
`autograd` makes backpropagation simple and reliable, but be mindful of gradient accumulation and disabling it during inference.

### 4. Defining Models with `nn.Module` (Network Structure)

#### Motivation
- `nn.Module` provides a unified way to organize parameters (weights/biases) and define forward logic, making models reusable and easy to save.

#### Core Concepts
- Create a model by inheriting from `torch.nn.Module` and implementing `__init__` (to define layers) and `forward()` (for the forward computation).
- A module's parameters are automatically available in `model.parameters()`, making it easy to pass them to an optimizer.

#### Use Cases/Modes
- Defining model architectures from linear regression and MLPs to CNNs and Transformers.

#### Example

```python
import torch
import torch.nn as nn

class SimpleNet(nn.Module):
    def __init__(self, in_features=784, hidden=128, out_features=10):
        super().__init__()
        self.fc1 = nn.Linear(in_features, hidden)
        self.act = nn.ReLU()
        self.fc2 = nn.Linear(hidden, out_features)

    def forward(self, x):
        x = self.fc1(x)
        x = self.act(x)
        x = self.fc2(x)
        return x

model = SimpleNet()
print(sum(p.numel() for p in model.parameters()))  # Total number of parameters
```

#### Notes/Best Practices
- Encapsulate reusable layers or sub-modules into separate `nn.Module` classes to improve code reuse and testing.
- Only write forward logic in `forward`. Do not modify model parameters inside `forward`.

#### Summary
`nn.Module` is the core abstraction for organizing model code and managing parameters. Mastering its use leads to clear and extensible model structures.

### 5. Loss Functions and Optimizers

#### Motivation
- A loss function measures the discrepancy between predictions and true values. An optimizer adjusts parameters based on gradients to minimize this loss.

#### Core Concepts
- **Common losses**: `nn.CrossEntropyLoss` (for classification), `nn.MSELoss` (for regression).
- **Common optimizers**: `torch.optim.SGD`, `torch.optim.Adam`, etc.
- The standard steps to update parameters are `optimizer.zero_grad()`, `loss.backward()`, and `optimizer.step()`.

#### Use Cases/Modes
- The choice of loss function should match the task type (classification, regression, multi-label, etc.).

#### Example

```python
import torch
import torch.nn as nn
import torch.optim as optim

model = SimpleNet()
criterion = nn.CrossEntropyLoss()
optimizer = optim.SGD(model.parameters(), lr=0.01)

# Dummy data example
inputs = torch.randn(16, 784)
labels = torch.randint(0, 10, (16,))

# Forward pass
outputs = model(inputs)
loss = criterion(outputs, labels)

# Backward and step
optimizer.zero_grad()
loss.backward()
optimizer.step()
```

#### Notes/Best Practices
- The learning rate (`lr`) has the biggest impact on convergence. It often requires tuning or the use of a learning rate scheduler (`torch.optim.lr_scheduler`).
- For deep models, Adam often provides a more stable starting point, while SGD (with momentum) can excel in large-scale training.

#### Summary
Choosing the right loss and optimizer and following the standard update steps are core to the deep model training process.

### 6. The Standard Training Loop (Train/Validation/Test)

#### Motivation
- The training loop is where a model learns from data: a forward pass computes the loss, a backward pass computes gradients, and the optimizer updates parameters. Performance is periodically evaluated on a validation set to check for generalization.

#### Core Concepts
- The training phase requires `model.train()` (to enable behaviors like dropout and batchnorm), while the validation/test phase uses `model.eval()` and runs under `torch.no_grad()` to disable gradient computation.
- **Common steps**: Data loading → `model(inputs)` → `loss` → `backward()` → `optimizer.step()` → `scheduler.step()` (optional).

#### Use Cases/Modes
- Mini-batch training. Each epoch iterates through the entire training set and evaluates on the validation set.

#### Example (Simplified Training Loop)

```python
for epoch in range(5):
    model.train()
    for batch_inputs, batch_labels in train_loader:
        batch_inputs = batch_inputs.to(device)
        batch_labels = batch_labels.to(device)

        optimizer.zero_grad()
        outputs = model(batch_inputs)
        loss = criterion(outputs, batch_labels)
        loss.backward()
        optimizer.step()

    # Validation
    model.eval()
    with torch.no_grad():
        val_loss = 0.0
        for v_inputs, v_labels in val_loader:
            v_inputs = v_inputs.to(device)
            v_labels = v_labels.to(device)
            v_outputs = model(v_inputs)
            val_loss += criterion(v_outputs, v_labels).item()
    print(f'Epoch {epoch} val_loss: {val_loss}')
```

#### Notes/Best Practices
- Use `DataLoader` (`torch.utils.data.DataLoader`) to organize and parallelize data loading.
- For reproducibility, set a random seed (`torch.manual_seed()`), but note that there may still be non-determinism in distributed or GPU environments.
- Periodically save model checkpoints (`torch.save(model.state_dict(), path)`).

#### Summary
A standard training loop includes both training and validation phases. A proper evaluation and checkpointing strategy is crucial for tuning and fault recovery.

### 7. Device Management (CPU/GPU) and Performance Tips

#### Motivation
- GPUs can significantly accelerate most deep learning tasks, but require correct management of device movement and memory to avoid errors and performance issues.

#### Core Concepts
- Use `device = torch.device('cuda')` to move tensors and models to the GPU: `model.to(device)`, `tensor.to(device)`.
- Avoid frequent data copying between devices in the training loop.

#### Use Cases/Modes
- Single-GPU / Multi-GPU training (using `nn.DataParallel` or `torch.distributed`). CPU is only for small-scale experiments or inference.

#### Example

```python
device = torch.device('cuda' if torch.cuda.is_available() else 'cpu')
model.to(device)

# Inside the training loop
for batch_inputs, batch_labels in train_loader:
    batch_inputs = batch_inputs.to(device)
    batch_labels = batch_labels.to(device)
    outputs = model(batch_inputs)
    # ...
```

#### Notes/Best Practices
- In multi-GPU scenarios, use `torch.nn.DataParallel` (simple) or `torch.distributed` (higher performance and scalability).
- Monitor GPU memory (`nvidia-smi`) and adjust the batch size to avoid Out-Of-Memory (OOM) errors.
- For I/O bottlenecks, use a multi-threaded `DataLoader` (`num_workers>0`) to speed up data loading.

#### Summary
Proper device management and data loading strategies can significantly improve training speed and reduce failures.

## Best Practices (Quick Reference)

- Use `with torch.no_grad()` during inference/validation to save memory.
- In the training loop, call `optimizer.zero_grad()`, then `loss.backward()`, then `optimizer.step()`.
- Save model parameters using `model.state_dict()` and load them with `model.load_state_dict()`.
- For cross-platform reproducibility, record the `torch` and `cuda` versions, random seeds, and data splits.
