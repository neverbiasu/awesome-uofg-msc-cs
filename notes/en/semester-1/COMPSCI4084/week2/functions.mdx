## Overview
- **Goal**: Master function definition and invocation, understand parameter passing and return mechanisms, and improve code reusability and modularity.
- **Scope**: Covers function definitions, various parameter types, local/global scope, and module imports. Does not cover advanced topics like decorators, closures, or higher-order functions.

## Learning Objectives
1. Master the syntax for function definition (`def`) and the mechanism for invocation.
2. Understand the differences and use cases for positional, keyword, and default arguments.
3. Be able to use the `return` statement to return values and use those results in a program.
4. Understand the scope and lifecycle of local and global variables.
5. Be able to import modules (built-in or custom) and call functions from them.

## Key Concepts

### 1. Function Definition and Invocation Basics
- **Motivation**: Encapsulate repetitive code into reusable functions to improve maintainability and readability.
- **Core Concepts**:
  - A function is a block of statements that performs a specific task and can be called from multiple places.
  - **Definition**: `def function_name(parameters): <body>`
  - **Invocation**: `function_name(arguments)`
  - The function body must be indented (usually 4 spaces).
- **Use Cases/Patterns**:
  - Extracting repetitive logic into a function.
  - Decomposing a complex task into smaller functions.
  - Providing a configurable interface.
- **Example**:
```python
# Simple function definition and invocation
# A greeting function with no parameters
def greet():
    print("Hello from function!")

greet()  # Output: Hello from function!

# Function with a parameter
# Takes a `name` parameter to print a personalized greeting
def greet_user(name):
    print(f"Hello, {name}!")

greet_user("Alice")  # Output: Hello, Alice!
```
- **Notes/Best Practices**:
  - Use `snake_case` for function names (e.g., `calculate_total`).
  - Functions should have a single responsibility and be kept short (ideally under 20 lines).
  - A function must be defined before it is called (or loaded automatically when a module is imported).
- **Summary**: Functions are defined with `def` and called by their name followed by parentheses. They are the basic unit of code reuse.

### 2. Parameter Types: Positional and Keyword Arguments
- **Motivation**: Different scenarios require different ways of passing arguments. Positional arguments are concise, while keyword arguments are highly readable.
- **Core Concepts**:
  - **Positional Arguments**: Passed in order and must match the parameter order in the definition.
  - **Keyword Arguments**: Passed by parameter name, so the order does not matter.
  - When mixing, positional arguments must come before keyword arguments.
- **Use Cases/Patterns**:
  - Use positional arguments for core, required parameters.
  - Use keyword arguments for optional configurations or when a function has many parameters, to improve readability.
  - In API design, place important parameters first, and make optional ones keyword-based.
- **Example**:
```python
# Function with multiple parameters
# Draws a rectangle; width and height are positional parameters
def draw_box(width, height, outline='*', fill=' '):
    """Draws a rectangle of a specified width and height."""
    for i in range(height):
        if i == 0 or i == height - 1:
            print(outline * width)
        else:
            print(outline + fill * (width - 2) + outline)

# Providing only positional arguments (outline and fill use defaults)
draw_box(5, 3)
# Output:
# *****
# *   *
# *****

# Mixing positional and keyword arguments
draw_box(4, 3, outline='#', fill='-')
# Output:
# ####
# #--#
# ####

# Pure keyword argument invocation (order doesn't matter)
draw_box(height=2, width=6, fill='.')
```
- **Notes/Best Practices**:
  - The order of positional arguments must match the definition.
  - Keyword arguments improve readability, especially with many parameters.
  - When mixing, positional arguments must come first: `func(1, 2, key=3)` ✅, `func(key=3, 1, 2)` ❌.
- **Trade-offs and Alternatives**:
  - Positional arguments are concise but order-dependent; keyword arguments are explicit but verbose.
  - If a function has too many parameters (>5), consider passing a configuration object or dictionary.
- **Summary**: Positional arguments are passed in order, keyword arguments by name. Follow the order rule when mixing them.

### 3. Default Arguments
- **Motivation**: Provide default values for optional parameters to reduce the number of arguments required at invocation and improve API flexibility.
- **Core Concepts**:
  - Specify a default value at definition: `def func(a, b=10):`
  - Arguments with default values can be omitted when the function is called.
  - Default arguments must follow non-default (positional) arguments.
- **Use Cases/Patterns**:
  - Optional configuration parameters (e.g., file encoding, log level).
  - Providing backward-compatible APIs (adding a new optional parameter doesn't break old code).
- **Example**:
```python
# Function with a default argument
# `name` defaults to 'Guest' and can be omitted
def greet(name='Guest'):
    print(f"Hello, {name}!")

greet()           # Output: Hello, Guest!
greet('Charlie')  # Output: Hello, Charlie!

# Multiple default arguments
# `a` and `b` have default values and can be selectively overridden
def add(a=0, b=0):
    return a + b

print(add())        # Output: 0
print(add(5))       # Output: 5
print(add(5, 3))    # Output: 8
print(add(b=10))    # Output: 10 (overriding only b)
```
- **Notes/Best Practices**:
  - **Trap**: Do not use mutable objects (like `[]` or `{}`) as default values. Use `None` instead and initialize in the function body.
  ```python
  # ❌ Incorrect example
  def append_item(x, bucket=[]):  # `bucket` is mutable and shared across calls
      bucket.append(x)
      return bucket

  # ✅ Correct way
  def append_item(x, bucket=None):
      if bucket is None:
          bucket = []
      bucket.append(x)
      return bucket
  ```
  - Default arguments must come after non-default arguments: `def func(a, b=10)` ✅, `def func(a=10, b)` ❌.
- **Summary**: Default arguments provide optional configurations and reduce required parameters. Avoid using mutable objects as default values.

### 4. Return Values and the `return` Statement
- **Motivation**: A function's computed result needs to be returned to the caller for subsequent use, rather than just being printed inside the function.
- **Core Concepts**:
  - The `return` statement returns a value and terminates the function's execution.
  - A function with no `return` statement, or a `return` with no value, returns `None` by default.
  - Any type can be returned: numbers, strings, lists, tuples, etc.
  - Multiple values can be returned (they are packed into a tuple).
- **Use Cases/Patterns**:
  - **Computation functions**: Return the result of a calculation.
  - **Query functions**: Return the data found.
  - **Transformation functions**: Return the processed data.
- **Example**:
```python
# Returning a single value
# Calculates and returns the product of two numbers
def multiply(a, b):
    return a * b

result = multiply(4, 5)
print(f"The product is {result}")  # Output: The product is 20

# Returning multiple values (as a tuple)
# Returns both the quotient and the remainder
def divide_with_remainder(a, b):
    quotient = a // b
    remainder = a % b
    return quotient, remainder  # Returns a tuple

q, r = divide_with_remainder(10, 3)
print(f"Quotient: {q}, Remainder: {r}")  # Output: Quotient: 3, Remainder: 1

# Conditional return
# Returns early based on a condition
def get_grade(score):
    if score >= 90:
        return 'A'
    elif score >= 80:
        return 'B'
    elif score >= 70:
        return 'C'
    return 'D'  # Default case

print(get_grade(85))  # Output: B
```
- **Notes/Best Practices**:
  - A function should have a clear return type (or document it in a comment).
  - Functions that only print (`print` instead of `return`) have limited reusability.
  - If there are multiple `return` paths, ensure all paths either return a value or all return `None`.
- **Trade-offs and Alternatives**:
  - Returning multiple values via tuple unpacking is intuitive but requires remembering the order. A dictionary or a data class can improve readability.
- **Summary**: `return` sends a result back to the caller. Functions that only print without returning are less reusable.

### 5. Variable Scope: Local and Global Variables
- **Motivation**: Understand a variable's visibility to avoid naming conflicts and accidental modification of global state.
- **Core Concepts**:
  - **Local Variables**: Defined inside a function, visible only within that function, and destroyed after the function returns.
  - **Global Variables**: Defined outside any function, visible throughout the program.
  - **Variable Shadowing**: A local variable with the same name as a global variable will "shadow" (hide) the global one inside the function.
  - Parameters and loop variables are also local.
- **Use Cases/Patterns**:
  - Use local variables for internal calculations to avoid polluting the global namespace.
  - Use uppercase for global constants (e.g., `MAX_SIZE = 100`).
  - To modify a global variable, use the `global` keyword (but this is not recommended).
- **Example**:
```python
# Variable shadowing example
# The local variable `x` inside the function does not affect the global `x`
x = 10  # Global variable

def foo():
    x = 5  # Local variable, shadows the global x
    print(f"Inside function: x = {x}")

foo()  # Output: Inside function: x = 5
print(f"Outside function: x = {x}")  # Output: Outside function: x = 10

# Parameters are also local variables
# `width` and `height` are only visible inside draw_box
def draw_box(width, height):
    for i in range(height):  # `i` is also a local variable
        print('*' * width)

draw_box(3, 2)
# print(width)  # Error! `width` does not exist outside the function
```
- **Notes/Best Practices**:
  - Prefer local variables to reduce global state.
  - Avoid modifying global variables inside functions. If needed, declare with `global`, but it's often a sign of poor design.
  - Variable shadowing can be confusing; be mindful of naming conflicts.
- **Trade-offs and Alternatives**:
  - To share state across functions, prefer passing arguments and returning values over using global variables.
  - For complex state management, consider using classes (object-oriented programming).
- **Summary**: Local variables are visible only within a function; global variables are visible everywhere. Prefer local variables to keep functions independent.

### 6. Imports and Reuse: Built-in Functions and Modules
- **Motivation**: Leverage Python's built-in functions and standard library to avoid reinventing the wheel. Organize code into modules for reuse across projects.
- **Core Concepts**:
  - **Built-in Functions**: Available directly, e.g., `print()`, `input()`, `len()`, `round()`.
  - **Standard Library Modules**: Need to be imported, e.g., `math`, `random`.
  - **Import Syntax**:
    - `import module`: Imports the whole module. Call functions with `module.function()`.
    - `from module import function`: Imports a specific function. Call it directly: `function()`.
  - **Custom Modules**: Define functions in a `.py` file, which can then be imported by other files.
- **Use Cases/Patterns**:
  - **Math calculations**: `import math` → `math.sqrt()`, `math.pi`.
  - **Random number generation**: `import random` → `random.randint()`, `random.choice()`.
  - **Cross-file reuse**: Place common functions in a separate module.
- **Example**:
```python
# Importing a built-in module
# Using math functions from the `math` module
import math

num = 16
print(math.sqrt(num))  # Output: 4.0
print(math.pi)         # Output: 3.141592653589793

# Partial import
# Importing only the needed functions simplifies calls
from random import randint, choice

dice = randint(1, 6)  # Generate a random integer from 1 to 6
color = choice(['red', 'blue', 'green'])  # Randomly select a color
print(f"Dice: {dice}, Color: {color}")

# Custom module example (assuming you have myutils.py)
# Contents of myutils.py:
# def add(a, b):
#     return a + b

# In another file, you can import it:
# import myutils
# result = myutils.add(5, 3)
```
- **Notes/Best Practices**:
  - Import statements are usually placed at the top of the file.
  - `import *` pollutes the namespace and is not recommended.
  - Module names should be short, lowercase, and without conflicts.
  - In a custom module, place test code inside an `if __name__ == '__main__':` block to prevent it from running on import.
- **Summary**: Use `import` to bring in built-in or custom modules and reuse existing functionality. The standard library offers a rich set of tools to reduce redundant development.

## Best Practices
- Use `snake_case` for function names; keep them descriptive and avoid reserved words.
- Avoid using mutable objects (`list`/`dict`) as default arguments. Use `None` and initialize in the function body instead.
- Functions should have a single responsibility and be kept short (ideally under 20 lines). Decompose complex logic into smaller functions.
- Prefer local variables. To share data between functions, pass it via arguments and return values, avoiding global variables.
- Returning a value is better than just printing. Ensure functions have a clear input-output contract.
- Place import statements at the top of the file. Avoid `import *`; explicitly import what you need.
