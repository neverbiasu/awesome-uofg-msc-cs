## Key Takeaway
Software security is about building software that remains dependable in the face of malicious attacks, moving beyond traditional reliability to address intentional threats.

## Reliability vs. Security
-   **Reliability**: Dealing with accidental failures (bugs, hardware errors).
-   **Security**: Dealing with **intentional, malicious** attacks by human adversaries.

### The CIA Triad
The core goals of security:
1.  **Confidentiality**: Ensuring data is accessible only to authorized users.
2.  **Integrity**: Protecting data from unauthorized modification.
3.  **Availability**: Ensuring systems are accessible when needed.

## Threats, Vulnerabilities, and Risks
-   **Threat**: A potential cause of an unwanted incident (e.g., an attacker).
-   **Vulnerability**: A weakness in the system (e.g., an unpatched bug).
-   **Risk**: The likelihood of a threat exploiting a vulnerability times the impact.

## Basic Security Principles
-   **Economy of Mechanism**: Keep designs simple.
-   **Fail-safe Defaults**: Default to "No Access".
-   **Complete Mediation**: Check every access to every object.
-   **Open Design**: Security shouldn't depend on secrecy of the algorithm (Kerckhoffs's Principle).
-   **Least Privilege**: Give users only the minimum access needed for their task.

## Examiner's Perspective: Technical Nuances

### Security as a Process
-   **Hard Red Line**: Security is **NOT** a one-time feature or a patch. It is a continuous process that must span the entire lifecycle.

### The Mindset
-   Thinking like an attacker is essential. Instead of asking "How does this work?", ask "How can I break this?".
