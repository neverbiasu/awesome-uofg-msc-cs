## Key Takeaway
Secure Software Development is a cultural and process-driven shift (DevSecOps) that prioritizes "Shift-Left" security, making security testing a continuous part of development rather than a final gate.

## 1. Secure SDLC (SSDLC)
A framework for building security into every phase of the traditional SDLC.
<Steps>

### SSDLC Phases
1.  **Preparation**: Training and defining security policies.
2.  **Requirements**: Misuse cases and STRIDE modeling.
3.  **Design**: Applying security principles and attack surface reduction.
4.  **Implementation**: Secure coding and SAST tools.
5.  **Testing**: DAST, Fuzzing, and Penetration testing.
6.  **Operations**: Incident response and continuous monitoring.
</Steps>

## 2. Measuring Security Maturity
How do organizations know if their security processes are working?
-   **BSIMM (Building Security In Maturity Model)**: A **descriptive** model based on what companies actually do.
-   **OpenSAMM**: A **prescriptive** model providing a roadmap for improvement.

## 3. DevOps to DevSecOps
-   **DevSecOps**: The integration of security practices into the DevOps pipeline.
-   **Automation**: Security checks (SAST, Dependency scanning) are automated as part of the build process.
-   **Feedback Loop**: Vulnerabilities found in production are fed back to development immediately.

## 4. Examiner's Perspective: Technical Nuances

### Shift-Left Security
-   **Nuance**: Finding a bug in the requirements phase costs $1\times$, while finding it in production can cost $100\times$. This is the primary economic justification for SSDLC.

### Software Bill of Materials (SBOM)
-   **Hard Red Line**: Modern applications are 80-90% third-party code. An SBOM is essential for tracking vulnerabilities in the supply chain (e.g., Log4j incident).
- *Exam Tip*: If asked how to protect against "Supply Chain Attacks", the answer must include **Software Composition Analysis (SCA)** and **SBOM**.
