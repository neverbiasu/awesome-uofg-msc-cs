## Overview

- **Goal**: To understand the runtime architecture of Apache Spark and its core components, and to master the complete workflow from job submission to execution.
- **Scope**: Covers Spark Compute components (Driver, Master, Worker, Executor), Execution Phases (DAG, Stage, Task), and comparison with Hadoop.

## Learning Objectives

1. **Identify** and describe Spark's core components (Client, Driver, Master, Worker, Executor) and their responsibilities.
2. **Explain** the Spark execution phases, including DAG construction, Stage division, and Task scheduling.
3. **Understand** the lifecycle of a Spark job, from `SparkContext` initialization to task execution and result retrieval.
4. **Compare** key architectural differences between Spark and Hadoop (e.g., in-memory computing, Driver lifecycle).

## Key Knowledge Points

### 1. Spark Compute Architecture

Spark's runtime architecture consists of several collaborating components:

- **Client**:
  - The software environment where the user submits the job.
  - Responsible for communicating with the Spark Master to submit work.
- **Driver**:
  - The **main program** that executes the Spark job (contains the `main` function).
  - Can run on the Client node or a node within the cluster.
  - Responsible for creating the `SparkContext`, parsing code, generating the DAG, and distributing tasks to Executors.
- **Spark Master**:
  - The resource manager. Receives work from the Client, analyzes the DAG, assigns resources, and communicates with the Driver.
  - Responsible for managing Worker nodes in the cluster.
- **Spark Worker**:
  - Manages local resources (CPU, RAM) on a node.
  - Responsible for launching and monitoring Executor processes.
- **Executor**:
  - A JVM process running on a Worker node.
  - Responsible for executing specific Tasks and storing data in memory or on disk.
  - Uses a ThreadPool to execute multiple Tasks concurrently.

### 2. Spark Execution Phases

Spark's execution process is **Lazy** and phased:

1.  **Initialization**: Client instantiates `SparkContext` (SC). SC interacts with the Cluster Manager and initializes the Driver.
2.  **RDD Creation**: SC is used to create input RDDs (partitioned across cluster nodes).
3.  **Transformations**: Transformations (e.g., `map`, `filter`) are applied to RDDs. **No computation** happens yet; only the sequence of operations (Lineage) is recorded to form a DAG (Directed Acyclic Graph).
4.  **Action**: Client uses an Action (e.g., `count`, `collect`) to trigger actual computation.
5.  **DAG Construction**: The `DAGScheduler` within the Driver breaks the DAG into **Stages**.
    - Stages are divided based on Shuffle dependencies (Wide Dependencies).
6.  **Task Scheduling**: `DAGScheduler` submits stages to the `TaskScheduler`.
7.  **Task Execution**: `TaskScheduler` launches **Tasks** on Executors.
    - Monitors progress and handles failures (Stragglers).
    - Executors return results to the Driver upon completion.

### 3. Job Execution Anatomy

A typical Spark job execution flow is as follows:

1.  **Run Program**: Start the Spark program, JVM launches.
2.  **Create Context**: `SparkContext` is initialized.
3.  **Init Driver**: Driver program starts and registers with Spark Master / Cluster Manager.
4.  **Request Resources**: Master instructs Workers to allocate resources for the application.
5.  **Launch Executors**: Workers start Executor processes (each job gets its own Executors).
6.  **Load Data & Create RDDs**: Driver defines RDDs and their dependencies.
7.  **Build DAG (Lazy)**: Execute Transformations, building the DAG incrementally without immediate calculation.
8.  **Trigger Action**: An Action is reached, sending the DAG to the `DAGScheduler`.
9.  **Split Stages**: `DAGScheduler` splits the graph into Stages based on boundaries (shuffles).
10. **Dispatch Tasks**: `TaskScheduler` ships Tasks to Executors.
11. **Execute Tasks**: Executors run Tasks in parallel, processing data partitions.
12. **Return Results**: Tasks complete, output is sent back to Driver or written to storage.
13. **Job Complete**: All Stages finish, Driver shuts down, releasing resources.

### 4. Important Differences (vs Hadoop)

- **Storage Layer**: Spark has no defined persistent storage layer (relies on HDFS, S3, etc.) but supports in-memory caching.
- **Driver Lifecycle**: The Spark Driver must remain alive until the Spark Job finishes (as it receives the final Action result).
- **Executor Isolation**: Each Job gets its own Executor on Workers to avoid memory sharing conflicts between jobs.
- **Startup Speed**: Spark job startup and task scheduling are generally faster than Hadoop MapReduce (Thread-level vs Process-level).

## Best Practices

- **Understand Lazy Evaluation**: Leverage Spark's laziness to avoid unnecessary intermediate computations.
- **Optimize Stages**: Minimizing wide dependencies (Shuffles) reduces the number of Stages and improves performance.
- **Resource Management**: Configure Executor memory and cores appropriately based on job scale.
