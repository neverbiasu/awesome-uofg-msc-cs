## Overview

- **Goal**: To master the most common basic transformations in Apache Spark and understand their working principles and use cases.
- **Scope**: Covers `map`, `filter`, `flatMap`, `mapPartitions`, `sample`, as well as the concept of Actions and using UDFs (User-Defined Functions).

## Learning Objectives

1. **Distinguish** between the concepts and purposes of Transformations and Actions.
2. **Master** the differences and usage of `map` and `flatMap`.
3. **Understand** the performance benefits and use cases of `mapPartitions`.
4. **Apply** `filter` for data cleaning.
5. **Know** how to define and use UDF interfaces in Java/Scala.

## Key Knowledge Points

### 1. Transformations vs Actions

Spark operations fall into two main categories:

- **Transformations**:
  - **Definition**: Operations that convert one (or more) RDD into another RDD.
  - **Characteristic**: **Lazy Evaluation**. Execution is not immediate; only the operation lineage is recorded.
  - **Examples**: `map`, `filter`, `flatMap`.
  - **Input/Output**: `RDD1 -> Transformation -> RDD2`.

- **Actions**:
  - **Definition**: Operations that trigger actual computation, usually returning results to the Driver or writing to external storage.
  - **Characteristic**: **Eager Execution**.
  - **Examples**: `collect` (returns Java List), `count`, `reduce`, `saveAsTextFile`.
  - **Input/Output**: `RDD -> Action -> Result (Object/File)`.

### 2. Common Basic Transformations

#### `map(func)`
- **Description**: Applies function `func` to **each element** of the source RDD, returning a new RDD.
- **Function Signature**: `record1 -> record2` (One-to-One).
- **Use Case**: Data cleaning, format conversion, field extraction.
- **Parallelism**: Processed in parallel across different partitions.

#### `flatMap(func)`
- **Description**: Similar to `map`, but each input item can be mapped to **0 or more** output items.
- **Function Signature**: `record1 -> Iterator<record2>` (One-to-Many).
- **Use Case**: Tokenization (splitting a line into words), flattening nested structures.

#### `filter(func)`
- **Description**: Returns a new dataset formed by selecting those elements on which `func` returns `true`.
- **Function Signature**: `record1 -> boolean`.
- **Use Case**: Data filtering, removing outliers.

#### `mapPartitions(func)`
- **Description**: Similar to `map`, but `func` runs separately on **each partition's** iterator, not on each element.
- **Function Signature**: `Iterator<record1> -> Iterator<record2>`.
- **Use Case**: Operations with high initialization costs (e.g., database connections). Connect once per partition instead of once per element.
- **Note**: Input partition must contain at least one record.

#### `mapPartitionsWithIndex(func)`
- **Description**: Similar to `mapPartitions`, but provides `func` with an integer value representing the partition index.
- **Function Signature**: `(index, Iterator<record1>) -> Iterator<record2>`.
- **Use Case**: When partition index is needed for processing, or for partition-specific logic.

#### `sample(withReplacement, fraction, seed)`
- **Description**: Samples a fraction of the data.
- **Parameters**:
  - `withReplacement`: Sample with or without replacement.
  - `fraction`: Fraction of data to sample.
  - `seed`: Random number generator seed.
- **Use Case**: Data exploration, approximation, test set generation. Acts as a random `filter`.

### 3. User-Defined Functions (UDFs)

Spark (Java/Scala API) uses specific interfaces to define transformation logic:

- **MapFunction**: For `map`.
- **FlatMapFunction**: For `flatMap`.
- **FilterFunction**: For `filter`.

When using PySpark or Databricks, these instructions are converted into underlying Spark function calls.

## Best Practices

- **Prefer mapPartitions**: If initialization (like network connections, parsing large objects) is expensive, use `mapPartitions` instead of `map` to significantly boost performance.
- **Use collect With Caution**: `collect` brings all results to the Driver's memory. If the dataset is large, it will cause an OOM (Out Of Memory) error on the Driver. Use only for small result sets.
- **Mind flatMap Memory**: `flatMap` generates more objects; be aware of potential memory pressure.
