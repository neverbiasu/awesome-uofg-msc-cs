# MapReduce

MapReduce is a programming model for processing large datasets in parallel across a distributed cluster. Introduced by Google in 2004, it revolutionized big data processing by providing a simple abstraction that hides the complexity of distributed computing.

## Core Concept

MapReduce breaks computation into two phases:

```
Input → [MAP] → Intermediate → [SHUFFLE] → [REDUCE] → Output
```

### The Map Phase

**Purpose**: Transform input data into intermediate key-value pairs.

```
map(key, value) → list[(key', value')]
```

- Processes one record at a time
- Runs in parallel across all input splits
- Outputs zero or more key-value pairs

### The Reduce Phase

**Purpose**: Aggregate values by key.

```
reduce(key, list[values]) → list[values']
```

- Receives all values for a given key
- Produces final output
- Runs in parallel across different keys

## Classic Example: Word Count

**Problem**: Count occurrences of each word in a document collection.

### Map Function

```python
def map(document_id, document_text):
    for word in document_text.split():
        emit(word, 1)
```

**Input**: `("doc1", "hello world hello")`

**Output**:
```
("hello", 1)
("world", 1)
("hello", 1)
```

### Reduce Function

```python
def reduce(word, counts):
    emit(word, sum(counts))
```

**Input**: `("hello", [1, 1])`

**Output**: `("hello", 2)`


## Key Components

### Partitioner

Determines which reducer receives each key.

```python
def partition(key, num_reducers):
    return hash(key) % num_reducers
```

- Default: Hash partitioning
- Custom partitioners for special requirements
- Ensures same key always goes to same reducer

### Combiner

Local aggregation before shuffle (optional optimization).

```
Map Output → [COMBINER] → Reduced data → Shuffle
```

<Callout type="info">
A combiner is like a "mini-reducer" that runs locally. It must be associative and commutative (e.g., sum, max, min).
</Callout>

**Example**: Word count with combiner

Without combiner:
```
Mapper 1: ("the", 1), ("the", 1), ("the", 1) → 3 records sent
```

With combiner:
```
Mapper 1: ("the", 3) → 1 record sent
```

### Shuffle and Sort

The framework automatically:
1. Partitions mapper output by key
2. Sorts data by key
3. Transfers data to appropriate reducers
4. Groups values by key for reducers

## MapReduce Patterns

### Filtering

Select records matching a criterion.

```python
def map(key, record):
    if meets_criteria(record):
        emit(key, record)

def reduce(key, records):
    for record in records:
        emit(key, record)
```

### Aggregation

Compute statistics (sum, avg, count).

```python
def map(key, record):
    emit(record.category, record.value)

def reduce(category, values):
    emit(category, sum(values))
```

### Join

Combine data from multiple sources.

**Reduce-side Join**:
```python
def map(key, record):
    # Tag records with source
    emit(record.join_key, ("source_A", record))
    # or
    emit(record.join_key, ("source_B", record))

def reduce(join_key, tagged_records):
    # Separate by source and combine
    a_records = [r for tag, r in tagged_records if tag == "source_A"]
    b_records = [r for tag, r in tagged_records if tag == "source_B"]
    for a in a_records:
        for b in b_records:
            emit(join_key, merge(a, b))
```

### Inverted Index

Build search index from documents.

```python
def map(doc_id, content):
    for word in content.split():
        emit(word, doc_id)

def reduce(word, doc_ids):
    emit(word, list(set(doc_ids)))
```

## Fault Tolerance

MapReduce provides automatic fault tolerance:

| Failure Type | Recovery Strategy |
|--------------|-------------------|
| Map task fails | Re-execute on another node |
| Reduce task fails | Re-execute; re-fetch map outputs |
| Node fails | Reschedule all its tasks |
| Master fails | Restart job (rare) |

**Key Principle**: Tasks are deterministic and idempotent—can be safely re-executed.

## Limitations of MapReduce

| Limitation | Description |
|------------|-------------|
| Batch only | Not suitable for real-time processing |
| Disk I/O | Intermediate data written to disk |
| Two-phase | Complex algorithms need multiple jobs |
| No iteration | Poor for iterative algorithms (ML) |
| High latency | Minutes to hours, not seconds |

<Callout type="warn">
MapReduce writes intermediate results to disk between map and reduce phases, causing significant I/O overhead for iterative algorithms.
</Callout>

## When to Use MapReduce

**Good for**:
- Batch processing of large datasets
- ETL (Extract, Transform, Load)
- Log analysis
- Building search indexes
- One-pass aggregations

**Not ideal for**:
- Interactive queries
- Real-time processing
- Iterative algorithms (use Spark instead)
- Small datasets

## Summary

| Concept | Description |
|---------|-------------|
| Map | Transform input to key-value pairs |
| Reduce | Aggregate values by key |
| Shuffle | Transfer and group data by key |
| Combiner | Local pre-aggregation optimization |
| Partitioner | Determines key-to-reducer mapping |
| Fault Tolerance | Automatic task re-execution |
