## Key Takeaway
Understanding the decoupling of presentation, logic, and data layers is fundamental to building scalable and maintainable web systems.

## 1. Web System Architecture
Most modern web applications follow a **3-Tier Architecture**. This separation allows for independent scaling and maintenance of each component.

### The 3-Tier Model
1.  **Presentation Tier (Frontend)**: The user interface, typically HTML, CSS, and JavaScript running in the browser.
2.  **Logic Tier (Middleware/Backend)**: Processes business logic, handles requests, and communicates with the data tier (e.g., Django, Express).
3.  **Data Tier (Database)**: Stores and manages the application's persistent data (e.g., PostgreSQL, MongoDB).
![System Architecture](/images/COMPSCI5012/week1/L1-IntroSysArchDBInfoArch-005.png)
<Callout type="info">
**Why 3-Tier?** It prevents a "monolithic" failure. If the UI needs a redesign, the database schema doesn't necessarily have to change.
</Callout>

## 2. Information Architecture (IA)
IA is about organizing, structuring, and labeling content in an effective and sustainable way.

### Core Components of IA
-   **Organization Schemes**: How you group information (Alphabetical, Chronological, Topic-based).
-   **Labeling Systems**: How you represent information (consistent terminology).
-   **Navigation Systems**: How users move through the information.
-   **Search Systems**: How users look for information.

## 3. Database Fundamentals
In this course, we focus on **Relational Databases (RDBMS)** using SQL.

### Relational Model Concepts
-   **Table (Relation)**: A set of data elements organized using model of vertical columns and horizontal rows.
-   **Primary Key**: A unique identifier for each record in a table.
-   **Foreign Key**: A field in one table that uniquely identifies a row of another table, establishing a relationship.
<Steps>

### Database Design Workflow
1.  **Requirement Analysis**: What data needs to be stored?
2.  **Conceptual Design**: Entity-Relationship (ER) Modeling.
3.  **Logical Design**: Mapping ER diagrams to tables.
4.  **Physical Design**: Indexing and performance tuning.
</Steps>

## 4. Examiner's Perspective: Technical Nuances

### Scaling: Vertical vs. Horizontal
-   **Vertical Scaling (Scaling Up)**: Adding more power (CPU, RAM) to an existing machine. Limited by hardware ceilings.
-   **Horizontal Scaling (Scaling Out)**: Adding more machines to the pool. Preferred for big data and high-traffic web apps.

### Data Integrity vs. Performance
-   Strict **Normalization** (3NF) reduces redundancy but can lead to complex joins that slow down read-heavy applications.
-   **Denormalization** can improve read performance but risks data inconsistency.
