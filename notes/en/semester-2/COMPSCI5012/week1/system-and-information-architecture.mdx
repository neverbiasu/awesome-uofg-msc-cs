## Overview

- **Goal**: To understand the architecture of modern Web Applications (from monolithic to tiered), the importance of Data Management, and user-centric Information Architecture design.
- **Scope**: Covers Web App classification, System Architecture patterns (Client-Server, N-Tier), Entity Relationship Diagrams (ERD) & Django Model mapping, and Information Architecture deliverables (Site Maps, User Flows, Wireframes).

## Learning Objectives

1. **Understand** the different types of Web Applications (Static, Interactive, Transactional, etc.) and their evolution.
2. **Master** the concept of Tiered Architectures, their benefits, and common patterns (2-Tier, 3-Tier).
3. **Interpret and create** High-level System Architecture diagrams and Entity Relationship Diagrams (ERDs).
4. **Apply** Information Architecture principles to develop User Requirements, Site Maps, User Flows, and Wireframes.

## Key Knowledge Points

### 1. Web Application Types & Evolution

- **Motivation**: The Web has evolved from static document sharing to complex distributed application systems. Understanding this classification helps in selecting the right technology stack.
- **Core Concepts**:
  - **Static**: Hand-built HTML pages, high maintenance, no server-side logic.
  - **Interactive**: Contains forms, menus; server-side dynamic generation (e.g., CGI, PHP).
  - **Transactional**: Involves data capture and database storage (e.g., E-commerce).
  - **Workflow-based**: Reflects business process sequences (e.g., Hotel booking).
  - **Collaborative/Social**: Multi-user sharing and interaction (e.g., Wikis, Facebook).
  - **Mobile/Ubiquitous**: Cross-device access and sensor integration.
- **Use Cases**:
  - Marketing Site -> Static/Interactive.
  - Enterprise System -> Transactional/Workflow-based.
- **Summary**: Web Application complexity increases with functional requirements, necessitating principled architectural design.

---

### 2. System Architecture

- **Motivation**: To manage complexity by splitting the system into components with single responsibilities. Architecture diagrams serve as blueprints for communication.
- **Core Concepts**:
  - **Monolithic**: UI, Logic, and Data mixed together (e.g., early Java Swing + File I/O). Not suitable for Web.
  - **Tiered Architecture**: Separates concerns into different levels/tiers.
    - **2-Tier (Client-Server)**:
      - **Thin Client**: Browser only renders HTML; Server handles all logic/data.
      - **Extended Thin Client**: Client handles some presentation logic (CSS/JS).
      - **Issues**: Client overload or Server bottleneck; Tight coupling.
    - **3-Tier**:
      - **Presentation Tier (Client)**: User Interface.
      - **Application Tier (Middleware)**: Business Logic, Processing (e.g., Django, App Server).
      - **Data Tier (Database)**: Data persistence and management.
    - **N-Tier**: Further splitting the Application layer (e.g., separate Web Server, App Server, Media Server, Load Balancing).
- **Example**:
  ```text
  [Client Browser] <--> [Load Balancer] <--> [Web Server] <--> [App Server (Django)] <--> [Database (MySQL)]
  ```

- **Key Principles**:
  - **Separation of Concerns**: Each tier focuses on its own responsibility.
  - **Scalability**: Tiers can be distributed across machines; replication handles increased load.
- **Summary**: Modern Web Apps typically use 3-Tier or N-Tier architectures for better maintainability, flexibility, and scalability.

### 3. Database Modelling

- **Motivation**: Data is the core of Web Apps. Efficient storage, retrieval, and management are essential.
- **Core Concepts**:
  - **ER Model (Entity Relationship Model)**: Abstract representation of data.
    - **Entities**: Rectangles (e.g., User, Product).
    - **Relationships**: Diamonds (e.g., Buys, Enrolls).
    - **Attributes**: Characteristics (e.g., Name, Price).
  - **Compressed Chen Notation**: Entities and Relationships in the diagram; Attributes listed separately to avoid clutter.
- **Django Mapping**:
  - 1-to-N: `models.ForeignKey`
  - 1-to-1: `models.OneToOneField`
  - M-to-N: `models.ManyToManyField`
- **Summary**: ER Diagrams are standard tools for database design and map directly to Django Models.

---

### 4. Information Architecture (IA)

- **Motivation**: Helping users "find" and "understand" information in digital spaces. Connects User Needs, Business Goals, and Content.
- **Core Concepts**:
  - **Deliverables**:
    1.  **User Requirements**: User Stories, Personas, MoSCoW prioritization (Must, Should, Could, Won't).
    2.  **Site Maps**: High-level structural blueprint showing page hierarchy.
    3.  **User Flows**: Diagrams showing the steps a user takes to complete a task.
    4.  **Wireframes**: Low-fidelity page layout sketches focusing on structure, not visual design.

- **Best Practices**:

  - **Accessibility**: Always provide `ALT` text for images; consider WCAG standards.
- **Summary**: IA is the foundation of UX design and should precede coding to reduce rework.

## Best Practices

- **Design First**: Use Architecture Diagrams, ERDs, and Wireframes to clarify thinking before coding.
- **Independence**: Ensure layers in System Architecture are independent (UI changes shouldn't break DB logic).
- **User-Centric**: Use Personas and User Flows to ensure features match real usage scenarios.
- **Accessibility**: Building accessible web apps is a professional requirement, not an optional feature.
