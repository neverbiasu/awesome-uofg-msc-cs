## Key Takeaway
HTTP is the foundational protocol of the web, and its stateless nature necessitates mechanisms like cookies and sessions to maintain application state across requests.

## 1. HTTP: The Foundation
HTTP (HyperText Transfer Protocol) is a request-response protocol in the client-server model.

### HTTP Characteristics
-   **Stateless**: Each request is independent. The server doesn't "remember" previous interactions.
-   **TCP/IP Based**: Reliable delivery of data.
-   **Methods**: `GET` (retrieve), `POST` (submit), `PUT` (update), `DELETE` (remove).
![HTTP Request/Response Cycle](/images/COMPSCI5012/week4/L4-ProtocolsMessagingCoursework-005.png)

## 2. Statelessness & State Management
Since HTTP is stateless, web applications use workaround methods to track users.

### State Management Techniques
-   **Cookies**: Small data fragments stored on the client (browser).
-   **Sessions**: Server-side storage mapped to a session ID (often stored in a cookie).
-   **URL Rewriting**: Embedding state in the URL (less secure).
<Callout type="warn">
**Security Nuance**: HTTPS (HTTP over TLS/SSL) is mandatory for transmitting sensitive state information to prevent eavesdropping and Man-in-the-Middle (MitM) attacks.
</Callout>

## 3. Web Messaging Protocols
Beyond standard HTTP, other protocols enable real-time or structured communication.
-   **WebSockets**: Full-duplex communication channel over a single TCP connection.
-   **REST (Representational State Transfer)**: An architectural style for networked applications using standard HTTP methods.

## 4. Examiner's Perspective: Technical Nuances

### Persistent vs. Non-Persistent Connections
-   **Non-Persistent**: One connection per object (HTML, then Image 1, then Image 2). High overhead.
-   **Persistent (HTTP/1.1+)**: Multiple objects can be sent over a single connection. Much faster.

### Status Codes to Remember
-   `200 OK`: Success.
-   `301/302`: Redirect.
-   `403 Forbidden` / `404 Not Found`: Client errors.
-   `500 Internal Server Error`: Server error.
