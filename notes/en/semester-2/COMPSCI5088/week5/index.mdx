## Summary

This week shifts focus from computation (Spark/MapReduce) to storage. It explores the evolution from local persistent storage to Network File Systems (NFS) and finally to the Hadoop Distributed File System (HDFS), designed for massive scale and fault tolerance on commodity hardware.

<Accordions>
  <Accordion title="Persistent Storage Primer">
    Understanding storage media (HDD vs SSD), RAID configurations for redundancy and performance, and the limitations of local storage for big data.
  </Accordion>
  <Accordion title="Network File Systems (NFS)">
    The first step towards distributed storage. Allowing remote access to files over a network. Limitations: Single point of failure (central server) and network bottlenecks.
  </Accordion>
  <Accordion title="HDFS Architecture">
    **NameNode** (Metadata Master) vs. **DataNode** (Block Storage). How HDFS splits large files into blocks (default 128MB) and replicates them (default 3x) for fault tolerance.
  </Accordion>
  <Accordion title="HDFS Operations">
    Detailed workflows for **Reading** (Client contacts NameNode for locations, then reads from DataNodes) and **Writing** (Pipeline replication strategy).
  </Accordion>
</Accordions>
