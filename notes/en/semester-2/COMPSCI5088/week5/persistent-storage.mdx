Before understanding HDFS, we must grasp the fundamentals of storage.

## Persistent Storage Primer

### Storage Media
- **HDD (Hard Disk Drive)**: Spinning platters. High capacity, low cost, slow random access (seek time). Good for sequential reads.
- **SSD (Solid State Drive)**: Flash memory. Fast random access, higher cost.

### RAID (Redundant Array of Independent Disks)
- **RAID 0**: Striping. Fast, no redundancy.
- **RAID 1**: Mirroring. Redundant, expensive (50% capacity).
- **RAID 5/6**: Parity. Good balance of speed and redundancy.

## Network File Systems (NFS)

NFS allows a user on a client computer to access files over a computer network much like local storage is accessed.

![NFS Architecture](/images/COMPSCI5088/week5/05-03-NFS-004.png)

### Limitations for Big Data
1.  **Centralization**: The file server is a bottleneck and a single point of failure.
2.  **Scalability**: Hard to scale storage capacity beyond a single server's limit.
3.  **Network Overhead**: Moving data to compute is expensive (Big Data principle: Move compute to data).

## Distributed Storage Concept

To solve NFS limitations, we distribute data across many machines.

![Distributed Storage](/images/COMPSCI5088/week5/05-02-DistributedStorage-005.png)

- **Sharding/Partitioning**: Splitting files into chunks.
- **Replication**: Storing copies on multiple nodes for fault tolerance.
