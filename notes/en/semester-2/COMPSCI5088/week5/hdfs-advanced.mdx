---
title: "HDFS Advanced Concepts"
description: High Availability, Federation, and Erasure Coding
---

As HDFS clusters grew, limitations in the original design led to several advanced features.

## High Availability (HA)

To address the **Single Point of Failure (SPOF)** of the NameNode:
- **Active/Standby NameNodes**: Two NameNodes running simultaneously.
- **JournalNodes**: Shared storage for edit logs to keep Standby synchronized.
- **ZooKeeper**: Handles automatic failover.

## HDFS Federation

To address the **Scalability Limit** of a single NameNode's memory:
- **Multiple NameNodes/Namespaces**: Each manages a slice of the file system (e.g., `/user`, `/data`).
- **Shared DataNodes**: All NameNodes share the same pool of storage.

## Small Files Problem

HDFS is inefficient with millions of small files because each file (regardless of size) requires an object in the NameNode's memory (~150 bytes).
- **Solution**: **Hadoop Archives (HAR)** or SequenceFiles to pack small files into larger ones.

## Erasure Coding (HDFS 3.x)

To reduce storage overhead from 3x replication (200% overhead):
- **Mechanism**: Like RAID 5/6 but distributed. Parity blocks are calculated.
- **Benefit**: Reduces storage overhead to ~50% while maintaining fault tolerance.
- **Trade-off**: Higher CPU usage for calculation and recovery.
