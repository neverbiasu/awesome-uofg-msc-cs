## Key Takeaway
HDFS provides a high-throughput, fault-tolerant storage layer for big data by decoupling file metadata (NameNode) from physical data blocks (DataNodes) and using rack-aware replication.

## HDFS Architecture
HDFS follows a Master-Slave pattern.
-   **NameNode (Master)**: Manages the file system namespace and metadata (file-to-block mapping).
-   **DataNode (Slave)**: Stores the actual data blocks and performs read/write requests from clients.
![HDFS Component Interaction](/images/COMPSCI5088/week5/05-04-HDFS-001.png)

## Metadata & Checkpointing
The NameNode keeps all metadata in RAM for fast access.
-   **Edit Log**: A transaction log that records every change to the file system.
-   **FsImage**: A snapshot of the file system state at a specific point in time.
-   **Secondary NameNode**: Periodically merges the Edit Log into the FsImage (Checkpointing) to prevent the Edit Log from becoming too large.
<Callout type="warn">
**Hard Red Line**: The Checkpoint **does not** store the physical location of blocks. Block locations are reported dynamically by DataNodes when they start up.
</Callout>

## Replication & Fault Tolerance
HDFS splits files into large blocks (default 128MB) and replicates them across the cluster.
-   **Replication Factor**: Usually 3.
-   **Rack Awareness**: HDFS places replicas on different racks to survive entire rack failures.
<Steps>

### The Write Protocol
1.  Client asks NameNode for permission and locations.
2.  NameNode returns a list of DataNodes for the first block.
3.  Client writes to the first DataNode.
4.  The first DataNode pipes data to the second, which pipes to the third (**Replication Pipeline**).
5.  Acks flow back to the client.
</Steps>

## Examiner's Perspective: Technical Nuances

### Decoupling Block Locations
-   **Why?**: If locations were stored in FsImage, a simple hardware upgrade or DataNode IP change would require an expensive disk update on the NameNode. By using dynamic **Block Reports**, the system remains flexible and I/O efficient.

### Replication Trade-offs
-   **Higher Replication**: Better read performance (parallelism), better reliability, but **lower write throughput** (more nodes to sync) and higher storage cost.
