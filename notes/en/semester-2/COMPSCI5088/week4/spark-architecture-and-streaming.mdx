Apache Spark is a powerful, distributed computing framework designed for fast processing of large datasets. Unlike Hadoop, which relies on disk-based storage (HDFS), Spark performs most operations in memory, achieving up to 100x speed improvements.

## Spark Architecture

The Spark ecosystem consists of several key components that coordinate to execute tasks across a cluster.

### Core Components

![Spark Architecture](/images/COMPSCI5088/week4/04-01-SparkArchitectuire-003.png)

- **Client**: Submits work to the cluster and communicates with the Spark Master.
- **Driver**: The central coordinator that executes the main program and builds the DAG.
- **Spark Master**: Manages the cluster resources and assigns work to workers.
- **Worker**: Manages local execution and communicates with the Master.
- **Executor**: A JVM process that runs tasks and caches data in memory.

### Execution Phases

Spark uses **Lazy Evaluation**, meaning transformations are not executed until an **Action** is called. This allows the DAG Scheduler to optimize the execution plan.

![Spark Execution Phases](/images/COMPSCI5088/week4/04-01-SparkArchitectuire-006.png)

1. **DAG Creation**: Transformations create a Directed Acyclic Graph.
2. **Stage Building**: The DAG Scheduler groups tasks into stages based on data dependencies.
3. **Task Scheduling**: The Task Scheduler ships tasks to Executors.

## Transformations & Actions

Spark operations are divided into two types:

### Transformations
These convert one RDD into another. They are lazy.
- **map**: Applies a function to each record.
- **filter**: Selects records that meet a condition.
- **reduceByKey**: Aggregates values for each key.
- **join**: Merges datasets based on keys (expensive).

### Actions
These trigger computation and return results.
- **collect**: Returns all data to the Driver (risk of OOM).
- **count**: Returns the number of elements.
- **saveAsTextFile**: Writes output to storage.

## Batch vs. Streaming

While batch processing handles static datasets, streaming handles continuous data arriving over time.

### Streaming Challenges

![Batch vs Streaming Example](/images/COMPSCI5088/week4/04-06-BatchVsStreaming-006.png)

- **State Management**: Keeping track of information across different batches (e.g., total spending per user).
- **Buffering & Back-pressure**: If input velocity exceeds processing capacity, buffers fill up, leading to system failure unless back-pressure is managed.

![Back Pressure Diagram](/images/COMPSCI5088/week4/04-06-BatchVsStreaming-028.png)

## Key Takeaway

- **Spark vs Hadoop**: Spark is faster due to in-memory computation and more versatile due to its rich API.
- **Immutability**: RDDs are immutable, which simplifies fault tolerance through lineage.
- **Streaming Latency**: Streaming prioritizes low latency per item, whereas batch prioritizes throughput.
