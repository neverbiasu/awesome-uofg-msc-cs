## Key Takeaway
MapReduce addresses the challenges of distributed work distribution by abstracting the complexity of data partitioning, task scheduling, and fault tolerance into two primary functions: Map and Reduce.

## Challenges of Distributed Computing
Distributing work across multiple machines introduces several complexities:
-   **Work Distribution**: How to split tasks evenly?
-   **Fault Tolerance**: What if a node fails?
-   **Data Locality**: Moving computation to the data is cheaper than moving data to the computation.

## The MapReduce Model
MapReduce is a programming model for processing large data sets with a parallel, distributed algorithm on a cluster.

### The Two Functions
1.  **Map**: Processes input pairs $(k1, v1)$ to produce intermediate pairs $(k2, v2)$.
2.  **Reduce**: Merges all intermediate values associated with the same intermediate key $k2$.
<Steps>

### The MapReduce Lifecycle
1.  **Input Split**: Data is divided into chunks.
2.  **Map Phase**: Parallel execution of map tasks.
3.  **Shuffle and Sort**: Intermediate data is grouped by key and transferred to reducers.
4.  **Reduce Phase**: Reducers process grouped data to produce the final output.
</Steps>

## Hadoop: The Implementation
Apache Hadoop is the open-source implementation of MapReduce.
-   **JobTracker (Hadoop 1.x)**: Coordinates jobs, assigns tasks to TaskTrackers.
-   **TaskTracker**: Executes tasks and reports progress.
<Callout type="info">
**LSM Connection**: The way MapReduce handles intermediate data (sorting in memory and spilling to disk) is conceptually similar to the **LSM Tree** write protocol.
</Callout>

## Examiner's Perspective: Technical Nuances

### Stragglers
-   **Concept**: A task that takes unusually long to finish, slowing down the entire job.
-   **Solution**: **Speculative Execution**. Hadoop identifies stragglers and schedules "backup" tasks on other nodes. The first one to finish wins.

### Serialization Overhead
-   **Nuance**: MapReduce relies heavily on disk I/O and network transfers for the Shuffle phase. Significant time is spent serializing/deserializing data, which is a major performance bottleneck compared to in-memory systems like Spark.
