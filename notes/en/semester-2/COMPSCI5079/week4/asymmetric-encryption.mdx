## Key Takeaway
Asymmetric encryption solves the key distribution problem of symmetric systems by using pairs of public and private keys, where security is derived from the mathematical difficulty of factoring large numbers or solving discrete logarithms.

## The Concept of Public-Key Crypto
Unlike symmetric crypto, each user has two keys:
-   **Public Key**: Shared with everyone. Used for encryption.
-   **Private Key**: Kept secret. Used for decryption.

### Use Cases
1.  **Encryption**: Send a message securely using the recipient's public key.
2.  **Digital Signature**: Prove origin using your private key.

## Diffie-Hellman Key Exchange (DH)
DH allows two parties to agree on a shared secret key over an insecure channel.
<Steps>

### DH Algorithm Steps
1.  Agree on a large prime $p$ and a generator $g$.
2.  Alice picks secret $a$, sends $A = g^a \mod p$.
3.  Bob picks secret $b$, sends $B = g^b \mod p$.
4.  Shared secret $K = B^a \mod p = A^b \mod p = g^{ab} \mod p$.
</Steps>

## RSA (Rivest-Shamir-Adleman)
The most widely used public-key algorithm.

### Key Generation
1.  Select two large primes $p, q$.
2.  Compute $n = p \times q$ and $\phi(n) = (p-1)(q-1)$.
3.  Select $e$ such that $1 < e < \phi(n)$ and $\gcd(e, \phi(n)) = 1$.
4.  Compute $d$ such that $d \cdot e \equiv 1 \pmod{\phi(n)}$.
-   **Public Key**: $(e, n)$
-   **Private Key**: $(d, n)$

## Examiner's Perspective: Technical Nuances

### Asymmetric vs. Symmetric Speed
-   **Hard Red Line**: Asymmetric encryption is significantly **slower** (100x to 1000x) than symmetric encryption (AES).
-   **Hybrid System**: In practice, we use RSA to exchange a session key, then use AES to encrypt the actual data.

### Security of RSA
-   Security depends on the difficulty of **Factoring $n$**. If an attacker can factor $n$ into $p$ and $q$, they can calculate $\phi(n)$ and then the private key $d$.
