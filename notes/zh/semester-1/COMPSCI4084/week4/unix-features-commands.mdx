## 概要
- 目标：掌握UNIX操作系统的核心特性、基本结构、文件系统概念及常用命令。
- 范围：覆盖UNIX多用户/多任务特性、内核与Shell、文件与目录管理、进程管理、权限控制、标准设备与管道、Shell脚本基础及常用命令速查；不涉及高级Shell编程或系统管理。

## 学习目标
1. 掌握UNIX操作系统的多用户、多任务、分层目录结构等主要特性。
2. 理解UNIX内核、Shell和实用工具在系统中的作用。
3. 能够使用`ls`, `cd`, `pwd`, `mkdir`, `rm`, `cp`, `mv`等基本文件管理命令。
4. 理解UNIX文件权限（rwx）及其对用户、组、其他人的影响，并能使用`chmod`修改权限。
5. 掌握进程管理的基本概念，并能使用`ps`和`kill`命令。
6. 理解UNIX标准设备（stdin, stdout, stderr）及其重定向和管道（`|`）的使用。

## 关键知识点

### 1. UNIX主要特性与基本结构
- **动机**：理解UNIX作为早期操作系统如何通过其独特设计支持多用户、多任务环境，并为现代操作系统奠定基础。
- **核心概念**：
  - **多用户 (Multi-user)**：允许多个用户同时共享同一计算机系统，通过时间片轮转处理器。
  - **多任务 (Multi-tasking)**：允许同时运行多个程序。
  - **分层目录结构 (Hierarchical Directory Structure)**：文件和目录以树状结构组织，便于管理。
  - **可移植性 (Portability)**：内核大部分用高级语言编写，易于移植到不同硬件。
  - **程序开发工具 (Tools for Program Development)**：提供丰富的编译器、调试器等支持。
  - **UNIX基本结构**：
    - **内核 (Kernel)**：操作系统的核心，负责调度程序、管理数据/文件访问、强制安全机制、执行硬件访问。
    - **Shell**：用户与内核交互的接口，解释用户命令，支持自定义环境。常见的Shell有`Bourne (sh)`, `Korn (krn)`, `C shell (csh)`, `Bash`。
    - **实用工具 (Utilities)**：提供文件管理（`rm`, `cat`, `ls`）、用户管理（`passwd`, `chmod`）、进程管理（`kill`, `ps`）等功能。
- **使用场景/模式**：日常文件操作、目录导航、文件共享和权限管理。
- **示例**：
```bash
# 查看当前使用的Shell
echo $SHELL
# 切换到Bash Shell
bash
```
- **注意事项/最佳实践**：Shell是用户与系统交互的关键，选择合适的Shell并熟悉其特性很重要。
- **小结**：UNIX以其多用户、多任务和模块化结构，通过内核、Shell和实用工具提供强大而灵活的计算环境。

### 2. 文件系统与文件管理
- **动机**：UNIX文件系统是组织和访问数据的核心机制，理解其结构和操作对于有效使用系统至关重要。
- **核心概念**：
  - **分层结构**：所有文件和目录都从根目录`/`开始组织。
  - **文件**：UNIX中一切皆文件，可以是数据、程序、设备等。每个文件有唯一的inode号。
  - **文件链接 (File Links)**：
    - **硬链接**：指向同一个inode，删除原文件不影响链接。
    - **软链接/符号链接 (`ln -s`)**：指向文件路径，删除原文件会导致链接失效。
  - **文件权限 (Security Rights)**：每个文件和目录有三组权限（所有者、组、其他人），每组包含读(`r`)、写(`w`)、执行(`x`)权限。
  - **文件管理命令**：
    - `ls`：列出目录内容。
    - `cd <dir>`：改变当前目录。
    - `pwd`：显示当前工作目录。
    - `mkdir <dir>`：创建目录。
    - `rm <file>`：删除文件。
    - `rm -r <dir>`：删除目录及其内容。
    - `cp <file1> <file2>`：复制文件。
    - `mv <file1> <file2>`：移动或重命名文件。
    - `touch <file>`：创建或更新文件时间戳。
    - `cat > <file>`：将标准输入写入文件。
    - `more <file>`：分页显示文件内容。
    - `head <file>`：显示文件开头10行。
    - `tail <file>`：显示文件末尾10行。
    - `tail -f <file>`：实时显示文件增长内容。
- **使用场景/模式**：日常文件操作、目录导航、文件共享和权限管理。
- **示例**：
```bash
# 列出当前目录所有文件（包括隐藏文件）及详细信息
ls -al
# 创建一个新目录
mkdir my_directory
# 复制文件
cp file1.txt file2.txt
# 移动文件并重命名
mv old_name.txt new_name.txt
# 创建一个软链接
ln -s /path/to/original_file /path/to/link
```
- **注意事项/最佳实践**：
  - 使用`rm -rf`时需格外小心，因为它赋予所有人完全权限，存在安全风险。
  - 理解硬链接和软链接的区别，避免误用。
  - 始终检查文件权限，确保数据安全。
- **小结**：UNIX文件系统以其分层结构和灵活的权限机制，通过一系列命令实现高效的文件和目录管理。

### 3. 文件权限与修改
- **动机**：文件权限是UNIX安全模型的基础，控制谁可以访问和操作文件，理解并正确设置权限至关重要。
- **核心概念**：
  - **权限类型**：读(`r`=4), 写(`w`=2), 执行(`x`=1)。
  - **权限对象**：所有者(u), 组(g), 其他人(o)。
  - **`chmod`命令**：修改文件或目录权限。
    - **符号模式**：`chmod u+x file.sh` (给所有者添加执行权限)。
    - **八进制模式**：`chmod 755 file.sh` (所有者rwx, 组rx, 其他人rx)。
  - **`chgrp`命令**：改变文件所属组。
  - **`chown`命令**：改变文件所有者。
- **使用场景/模式**：设置脚本可执行权限、限制敏感文件访问、调整文件所有权。
- **示例**：
```bash
# 给文件所有者添加执行权限
chmod u+x myscript.sh
# 设置文件权限为所有者读写执行，组和其他人只读执行
chmod 755 myfile.txt
# 改变文件所属组
chgrp newgroup myfile.txt
# 改变文件所有者
chown newowner myfile.txt
```
- **注意事项/最佳实践**：
  - 避免使用`chmod 777`，除非绝对必要，因为它赋予所有人完全权限，存在安全风险。
  - 目录的执行权限意味着可以进入该目录。
- **小结**：`chmod`命令通过符号或八进制模式，精确控制文件和目录的读、写、执行权限，是UNIX安全管理的核心。

### 4. 进程管理
- **动机**：理解UNIX如何管理运行中的程序（进程）对于监控系统性能、终止无响应程序和后台运行任务至关重要。
- **核心概念**：
  - **进程 (Process)**：UNIX系统中每个运行的程序实例。
  - **进程控制块 (PCB)**：UNIX为每个进程构建的数据结构，包含优先级、状态、寄存器信息等。
  - **进程管理命令**：
    - `ps`：列出当前活跃进程。
    - `top`：实时显示所有运行进程及其资源占用。
    - `kill <pid>`：终止指定PID的进程。
    - `killall <proc>`：终止所有名为`<proc>`的进程。
    - `&`：在后台运行命令。
    - `bg`：列出停止或后台作业，并在后台恢复停止的作业。
    - `fg`：将最近的作业带到前台。
- **使用场景/模式**：查找占用资源的进程、强制关闭程序、在不阻塞终端的情况下运行长时间任务。
- **示例**：
```bash
# 列出所有进程
ps aux
# 查找特定进程
ps aux | grep myprogram
# 终止进程
kill 12345 # 12345是进程ID
# 在后台运行一个脚本
./my_script.sh &n```
- **注意事项/最佳实践**：
  - 使用`kill`命令时要确保终止的是正确的进程，避免误杀关键系统进程。
  - `kill -9 <pid>`是强制终止，不给进程清理时间，应谨慎使用。
- **小结**：UNIX通过`ps`、`top`、`kill`等命令提供强大的进程管理能力，支持前后台运行和进程终止。

### 5. UNIX标准设备、重定向与管道
- **动机**：UNIX的“一切皆文件”哲学延伸到输入/输出，通过标准设备、重定向和管道，可以灵活地连接程序和数据流。
- **核心概念**：
  - **标准设备**：
    - `stdin` (0)：标准输入，通常是键盘。
    - `stdout` (1)：标准输出，通常是屏幕。
    - `stderr` (2)：标准错误，通常是屏幕。
  - **设备重定向**：
    - `>`：将`stdout`重定向到文件，覆盖原有内容。
    - `>>`：将`stdout`重定向到文件，追加到原有内容。
    - `&lt;`：将文件内容重定向为`stdin`。
    - `2>`：将`stderr`重定向到文件。
  - **管道 (`|`)**：将一个命令的`stdout`连接到另一个命令的`stdin`，实现数据流的串联处理。
- **使用场景/模式**：将命令输出保存到文件、从文件读取输入、组合多个命令完成复杂任务。
- **示例**：
```bash
# 将ls命令的输出保存到文件
ls > file_list.txt
# 将错误信息保存到文件
command_that_fails 2> error.log
# 将一个命令的输出作为另一个命令的输入
ls -l | grep ".txt"
# 组合多个命令
cat log.txt | grep "ERROR" | sort > sorted_errors.txt
```
- **注意事项/最佳实践**：
  - 理解`>`和`>>`的区别，避免意外覆盖文件。
  - 管道是UNIX哲学“小工具做一件事并做好”的体现，通过组合实现强大功能。
- **小结**：UNIX通过标准设备、灵活的重定向操作符和强大的管道机制，实现了程序间高效的数据流管理和复杂任务的组合执行。

### 6. Shell脚本基础
- **动机**：Shell脚本允许将一系列UNIX命令组合成可执行文件，自动化重复性任务，提高效率。
- **核心概念**：
  - **Shell脚本文件**：包含一系列UNIX命令的文本文件。
  - **可执行权限**：脚本文件需要`+x`权限才能直接运行。
  - **变量**：Shell支持内置变量和用户自定义变量，通过`$`符号访问。
  - **控制结构**：支持`for`, `while`, `if`, `select`等编程结构。
  - **命令替换**：使用`` `command` ``或`$(command)`将命令输出作为变量或参数。
- **使用场景/模式**：自动化系统维护、数据处理、部署任务等。
- **示例**：
```bash
#!/bin/bash
# 这是一个简单的Shell脚本
echo "Hello, World!"
NAME="User"
echo "Hello, $NAME!"

# 循环示例
for i in 1 2 3; do
  echo "Count: $i"
done

# 条件判断
if [ -f "myfile.txt" ]; then
  echo "myfile.txt exists."
else
  echo "myfile.txt does not exist."
fi
```
- **注意事项/最佳实践**：
  - 脚本开头通常包含`#!/bin/bash`（shebang），指定解释器。
  - 变量赋值时等号两边不能有空格。
  - 引用变量时使用双引号`"`可以保留空格和特殊字符的字面意义。
  - 谨慎处理特殊字符，使用引号避免意外解释。
- **小结**：Shell脚本通过组合命令、变量和控制结构，提供了一种强大的自动化工具，简化了UNIX环境下的重复性任务。

## 最佳实践
- 熟悉并善用`man`命令获取命令帮助。
- 在使用`rm -rf`等破坏性命令前，务必再三确认目标。
- 充分利用管道`|`和重定向`>` `<` `>>`组合命令，提高工作效率。
- 编写Shell脚本时，始终添加shebang，并赋予执行权限。
- 理解文件权限的含义，并根据需要合理设置，避免过度授权。
- 善用`ps`和`kill`命令监控和管理系统进程。
