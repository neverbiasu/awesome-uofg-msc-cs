## 概要
- 目标：掌握Shell中元字符的特殊含义、引用机制，理解Shell变量的定义与使用，并能运用命令组合操作符控制命令执行流程。
- 范围：覆盖Shell元字符（如通配符、变量扩展符）、单引号、双引号、反斜杠的引用和转义规则，Shell变量的定义、赋值、引用和取消设置，以及`;`, `&&`, `||`等命令组合操作符的逻辑；不涉及高级Shell脚本函数或数组。

## 学习目标
1. 理解Shell中元字符的特殊含义，如文件名扩展、变量扩展。
2. 掌握使用单引号、双引号和反斜杠来控制Shell对元字符的解释。
3. 能够定义、赋值、引用和取消设置Shell变量。
4. 了解命令替换的两种方式（反引号和`$()`）。
5. 能够运用`;`, `&&`, `||`等操作符组合多个命令，实现顺序、条件或备选执行。

## 关键知识点

### 1. Shell元字符与引用
- **动机**：Shell中的某些字符具有特殊含义（元字符），理解它们的作用以及如何引用/转义它们，对于编写正确的命令和脚本至关重要。
- **核心概念**：
  - **元字符 (Metacharacters)**：对Shell有特殊含义的符号，如`#`, `~`, `$`, `*`, `\`, `"`, `'`, `&`, `;`, `|`, `>`等。
  - **文件名扩展 (Filename Expansion / Wildcards)**：`*`匹配任意字符序列，`?`匹配单个字符。
  - **变量引用**：`$`用于引用变量的值。
  - **命令分隔符**：`;`用于分隔多个命令。
  - **后台执行**：`&`用于在后台运行命令。
  - **引用 (Quotations)**：
    - **无引号**：Shell会解释所有元字符，如`*`会被扩展为文件名。
    - **双引号 (`"`)**：阻止文件名扩展，但允许变量扩展和命令替换。保留空格。
    - **单引号 (`'`)**：阻止所有元字符的解释，包括变量扩展和命令替换。所有字符都被视为字面值。
  - **转义 (Escaping)**：`\`（反斜杠）用于移除单个字符的特殊含义。
- **使用场景/模式**：处理包含特殊字符的文件名、在字符串中保留空格、防止变量被意外扩展。
- **示例**：
```bash
# 无引号：*会被扩展为当前目录下的所有文件
echo *

# 双引号：*不会被扩展，但$USER会被扩展
echo "The current user is $USER and the file is *"

# 单引号：所有字符都被视为字面值
echo 'The current user is $USER and the file is *'

# 转义：移除$的特殊含义
echo The price is \$10
```
- **注意事项/最佳实践**：
  - 始终使用引号来保护包含空格或特殊字符的字符串，避免Shell的意外解释。
  - 单引号提供最强的保护，双引号提供部分保护（允许变量扩展）。
  - `\`用于转义单个元字符。
- **小结**：通过理解Shell元字符和灵活运用引用/转义机制，可以精确控制Shell对命令和字符串的解释，避免意外行为。

### 2. Shell变量
- **动机**：Shell变量允许存储和重用数据，是编写灵活和可维护脚本的基础。
- **核心概念**：
  - **定义与赋值**：`VAR_NAME=value`。等号两边不能有空格。如果值包含空格，需要用引号。
  - **引用**：`$VAR_NAME` 或 `${VAR_NAME}`。花括号在变量名与其他字符紧邻时尤其有用。
  - **取消设置 (Unsetting)**：`unset VAR_NAME`。
  - **内置变量**：Shell提供一些预定义的变量，如`PATH`, `HOME`, `USER`等。
  - **命令替换**：使用反引号 `` `command` `` 或 `$(command)` 将命令的输出赋值给变量。
- **使用场景/模式**：存储路径、文件名、用户输入、命令输出等。
- **示例**：
```bash
# 定义一个变量
NAME="Alice"
echo "Hello, $NAME!"

# 变量值包含空格
GREETING="Good morning"
echo "$GREETING, $NAME!"

# 变量名与字符串紧邻时使用花括号
FILE_PREFIX="report"
DATE=$(date +%Y%m%d)
REPORT_FILE="${FILE_PREFIX}_${DATE}.txt"
echo "Report file: $REPORT_FILE"

# 取消设置变量
unset NAME
echo "Name after unset: $NAME"
```
- **注意事项/最佳实践**：
  - 变量名通常使用大写字母和下划线。
  - 引用变量时，最好使用双引号，以防止Shell对变量值进行不必要的解释（如文件名扩展）。
  - `$(command)`是比反引号更推荐的命令替换方式，因为它支持嵌套。
- **小结**：Shell变量是Shell脚本中存储和操作数据的基本工具，通过定义、引用和命令替换，可以实现脚本的动态性和自动化。

### 3. 命令组合与执行逻辑
- **动机**：在命令行或脚本中，经常需要按特定顺序或条件执行多个命令，理解命令组合操作符的逻辑至关重要。
- **核心概念**：
  - **`;` (分号)**：顺序执行命令，无论前一个命令成功或失败。
  - **`&&` (逻辑与)**：只有前一个命令成功（退出状态为0）时，才执行后一个命令。
  - **`||` (逻辑或)**：只有前一个命令失败（退出状态非0）时，才执行后一个命令。
  - **`()` (子Shell)**：在子Shell中执行命令，不会影响当前Shell的环境变量和工作目录。
- **使用场景/模式**：
  - 顺序执行一系列不相关的命令。
  - 条件性地执行命令（如：`mkdir mydir && cd mydir`）。
  - 提供备选命令（如：`command1 || command2`）。
- **示例**：
```bash
# 顺序执行
echo "First command"; echo "Second command"

# 逻辑与：只有mkdir成功才cd
mkdir new_project && cd new_project

# 逻辑或：如果command_that_fails失败，则执行echo
false || echo "Previous command failed"

# 在子Shell中执行，不影响当前Shell的pwd
(cd /tmp && pwd)
pwd # 仍然是原来的目录
```
- **注意事项/最佳实践**：
  - `&&`和`||`常用于构建条件执行链，提高脚本的健壮性。
  - `()`创建子Shell，可以隔离命令执行环境，避免副作用。
- **小结**：通过`;`, `&&`, `||`等操作符，可以灵活控制命令的执行流程，实现复杂的逻辑组合。

## 最佳实践
- 编写Shell脚本时，始终使用引号保护字符串，特别是包含空格或特殊字符的字符串。
- 优先使用`$(command)`进行命令替换，因为它比反引号更易读且支持嵌套。
- 善用`&&`和`||`构建健壮的命令链，确保只有在预期条件下才执行后续操作。
- 对于不熟悉的Shell特性，查阅`man bash`或在线资源。
- 避免在变量赋值时等号两边留有空格。
