- 目标是掌握安全、可读、可维护的文件操作写法，并学会处理常见错误情形。

## 关键知识点

### 文件类型：文本 vs 二进制

#### 动机
- 不同数据需要不同的表示：可读文本（日志、配置、CSV）与二进制（图片、音频、模型权重）。选择错误的模式会导致数据损坏或解码错误。

#### 核心概念
- **文本文件**：使用字符编码（如 `UTF-8`），以字符串形式读写，使用模式 `r`, `w`, `a`（或带 `t` 的显式模式如 `rt`、`wt`）。
- **二进制文件**：读写原始字节，使用模式带 `b`，例如 `rb`, `wb`, `ab`。
- `encoding` 参数（文本模式）决定如何将字节转换为字符。

#### 使用场景/模式
- 文本：日志文件、配置、可读表格（CSV）等。
- 二进制：图片、音频、压缩文件、机器学习模型的二进制序列化（如 .pth/.bin）等。

#### 示例
```python
# 文本模式
with open('notes.txt', 'w', encoding='utf-8') as f:
    f.write('这是一些文本\n')
# 二进制模式（保存图片/模型）
with open('image.jpg', 'rb') as f:
    data = f.read()  # bytes
with open('model.bin', 'wb') as f:
    f.write(b"\x00\x01\x02")
```

#### 注意事项/最佳实践
- 总是明确指定 `encoding='utf-8'`（尤其是在可跨平台的项目中）。
- 写二进制时使用 `wb`，不要在二进制文件上使用文本模式。

#### 权衡与替代
- 将文本当二进制处理可以减少编码问题，但不便于人工阅读和文本操作。

#### 小结
选择正确的文件类型和打开模式是文件操作的第一步，能避免大多数读写错误。

### 打开文件与访问模式

#### 动机
- 打开文件前需确定访问意图（只读、覆盖写入、追加、新建），不正确的模式会导致数据丢失或程序崩溃。

#### 核心概念
- 常用模式：`r`（读）、`w`（写，覆盖）、`a`（追加）、`x`（独占写，若存在则失败）。
- 二进制模式：在模式后加 `b`（如 `rb`、`wb`）。
- `open()` 返回一个文件对象，需最后关闭（或使用 `with`）。

#### 使用场景/模式
- `r`：读取已有文件。
- `w`：覆盖写入，慎用（会清空已有文件）。
- `a`：在文件末尾追加，常用于日志。
- `x`：创建新文件，若存在则抛出 `FileExistsError`。

#### 示例
```python
# 读取
f = open('data.txt', 'r', encoding='utf-8')
content = f.read()
# 推荐：使用 with（见下节）
# 写入（覆盖）
with open('out.txt', 'w', encoding='utf-8') as f:
    f.write('覆盖写入\n')
# 追加
with open('out.txt', 'a', encoding='utf-8') as f:
    f.write('追加一行\n')
```

#### 注意事项/最佳实践
- 避免使用 `w` 对重要文件直接覆盖。若需要修改可先写到临时文件再替换（原子写）。
- 对于 CSV，用 `newline=''` 与 `encoding` 配合以避免多余空行或编码问题（详见 CSV 小节）。

#### 权衡与替代
- `x` 模式适合需要确保不覆盖旧数据的场景，但若并发环境可能仍需额外的文件锁。

#### 小结
正确选择 `open()` 的模式并结合上下文管理器能最大限度降低数据丢失风险。

### 读取方法：`read`, `readline`, `readlines`, 迭代

#### 动机
- 文件可能很大（数 GB），一次性 `read()` 会耗尽内存；有时需要逐行处理或按块读取来节省内存并提高效率。

#### 核心概念
- `read(size)`：读取指定字节/字符数（文本模式按字符数，二进制按字节）。
- `read()`：不传参数时读取整个文件（慎用）。
- `readline()`：读取一行，遇到末尾返回空字符串。
- `readlines()`：将文件所有行读为列表（每行为一个元素）。
- 直接迭代文件对象：`for line in f:` 是常见且内存友好的逐行读取方式。

#### 使用场景/模式
- 小文件：可以 `read()` 或 `readlines()`。
- 大文件或流式处理：逐行迭代或 `read(size)` 分块读取。

#### 示例
```python
# 逐行遍历（推荐）
with open('large.log', 'r', encoding='utf-8') as f:
    for line in f:
        process(line)
# readline() 循环
with open('data.txt', 'r', encoding='utf-8') as f:
    while True:
        line = f.readline()
        if not line:
            break
        print(line.rstrip())
# read(size) 分块处理（适合二进制或超大文件）
with open('big.bin', 'rb') as f:
    chunk_size = 1024 * 1024  # 1 MB
    while chunk := f.read(chunk_size):
        handle_bytes(chunk)
```

#### 注意事项/最佳实践
- 避免使用 `read()` 读取非常大的文件。
- `readlines()` 也会将所有行加载到内存中，不适合大文件。
- 使用 `for line in f` 是 Pythonic 且高效的做法。

#### 权衡与替代
- 若需要随机访问文件内容，考虑 `mmap` 模块或数据库替代品。

#### 小结
针对不同文件大小与处理需求选择合适的读取方法，优先逐行迭代以节省内存。

### 写入方法与 CSV 文件处理

#### 动机
- 文本写入简单但在处理表格数据（CSV）时需要注意换行、引号、分隔符与编码，手动拼接可能产生格式错误或 CSV 注入风险。

#### 核心概念
- `write()`：写入字符串，**不会**自动换行；需显式使用 `\n`。
- `writelines()`：接受一个字符串序列并按顺序写入（不会自动插入换行）。
- `csv` 模块：`csv.reader`, `csv.writer` 提供安全的 CSV 解析与输出，处理引号、转义和分隔符。
- 打开 CSV 文件时推荐传入 `newline=''` 并指定 `encoding`。

#### 使用场景/模式
- 日志、普通文本使用 `write`/`append`。
- 表格数据读写使用 `csv` 模块或 `pandas`（当需要更强大的数据处理时）。

#### 示例
```python

rows = [
    ['name', 'age'],
    ['Alice', '30'],
    ['Bob', '25'],
]
# 写 CSV（推荐写法）
with open('people.csv', 'w', encoding='utf-8', newline='') as csvfile:
    writer = csv.writer(csvfile)
    writer.writerows(rows)
# 读 CSV
with open('people.csv', 'r', encoding='utf-8', newline='') as csvfile:
    reader = csv.reader(csvfile)
    for row in reader:
        print(row)
```

#### 注意事项/最佳实践
- 在 Windows 平台上若不指定 `newline=''`，使用 `csv` 写文件可能会产生多余的空行。
- 对于非简单表格或需要数据分析的场景，使用 `pandas.read_csv()` / `DataFrame.to_csv()` 会更方便。
- 处理 CSV 时注意输入验证，避免 CSV 注入（例如：不要把未验证的用户输入写为以 `=`、`+` 开头的单元格，或对它们加引号）。

#### 权衡与替代
- 需要高性能或大规模数据处理时，考虑专用二进制格式（如 Parquet）或数据库。

#### 小结
使用 `csv` 模块并搭配 `newline=''` 与 `encoding` 可以确保跨平台、正确的 CSV 读写。

### 上下文管理器（`with`）与资源安全

#### 动机
- 忘记关闭文件会导致资源泄漏、文件句柄耗尽或写入数据未 flush（尤其在异常发生时）。`with` 能保证正确释放资源。

#### 核心概念
- `with open(...) as f:` 会在代码块结束时自动调用 `f.close()`，即使块内抛出异常也会执行关闭操作。
- 上下文管理器也可用于锁、数据库连接和其它需要明确释放的资源。

#### 使用场景/模式
- 几乎所有文件读写场景都应使用 `with`。
- 需要在异常路径也确保资源释放时使用上下文管理器。

#### 示例
```python
# 推荐写法：自动关闭文件
with open('data.txt', 'r', encoding='utf-8') as f:
    for line in f:
        process(line)
# 离开 with 块时文件自动关闭
```

#### 注意事项/最佳实践
- 不要在 `with` 内部手动调用 `close()`（冗余）。
- 多个资源可在同一 `with` 中管理：`with open(a) as fa, open(b) as fb:`。

#### 权衡与替代
- 若需更复杂的清理逻辑，可自定义上下文管理器（实现 `__enter__`/`__exit__` 或使用 `contextlib.contextmanager`）。

#### 小结
使用 `with` 是保证文件与其它资源安全释放的优雅方式，应作为默认模式。

### 异常处理：`try` / `except` / `finally` / `else`

#### 动机
- IO 操作（文件不存在、权限不足、解码错误）常会抛出异常。合理捕获并处理异常能提高程序健壮性并给用户有意义的提示。

#### 核心概念
- `try` 块中放可能抛异常的代码；`except` 捕获指定或任意异常；`finally` 保证无论是否异常都会执行的清理代码；`else` 在没有异常时执行。
- 常见异常类型：`FileNotFoundError`, `PermissionError`, `IsADirectoryError`, `UnicodeDecodeError`, `ValueError`。

#### 使用场景/模式
- 用户可控输入（如文件名）应捕获 `FileNotFoundError` 并提示重试。
- 对特定异常做精确处理，避免用裸 `except:` 捕获所有异常（会掩盖 bug）。

#### 示例
```python

filename = sys.argv[1] if len(sys.argv) > 1 else 'data.txt'
try:
    with open(filename, 'r', encoding='utf-8') as f:
        print(f.read())
except FileNotFoundError:
    print(f"文件未找到: {filename}")
except PermissionError:
    print(f"无法访问文件（权限不足）: {filename}")
except UnicodeDecodeError:
    print(f"文件编码错误，无法以 UTF-8 解码: {filename}")
except Exception as e:
    # 最后兜底，但记录异常信息以便调试
    print(f"发生意外错误: {e}")
else:
    print("读取成功")
finally:
    # 在使用 with 时通常不需要在 finally 中关闭文件，但其他清理工作可放在这里
    print("程序结束")
```

#### 注意事项/最佳实践
- 优先捕获具体异常类型，避免使用裸 `except:`。
- 在异常处理里记录足够的上下文（文件名、操作、时间戳）以便排查。
- 不要滥用异常来控制正常逻辑流程（异常开销较大）。

#### 权衡与替代
- 某些场景下用预检查（如 `os.path.exists()`）可以避免异常，但会引入竞态条件；通常更稳妥的做法是“EAFP”（尝试并捕获异常）模式。

#### 小结
使用 `try/except` 精确地捕获并处理异常，结合日志记录与用户提示，能显著提高程序的健壮性。

### 命令行参数与脚本化（`sys.argv`）

#### 动机
- 通过命令行参数让脚本可复用和自动化，便于构建小工具、管道脚本和批处理任务。

#### 核心概念
- `sys.argv` 是存放命令行参数的列表：`sys.argv[0]` 是脚本名，后续为传入的参数。
- 对更复杂的参数解析，优先使用 `argparse` 模块而非直接解析 `sys.argv`。

#### 使用场景/模式
- 简单脚本读取一个或两个参数时使用 `sys.argv`。当需要选项、帮助信息或类型转换时使用 `argparse`。

#### 示例
```python
# simple_arg.py

if len(sys.argv) < 2:
    print('用法: python simple_arg.py <filename>')
    sys.exit(1)
filename = sys.argv[1]
try:
    with open(filename, 'r', encoding='utf-8') as f:
        print(f.read())
except FileNotFoundError:
    print('文件未找到')
```
使用 `argparse` 的更好示例：
```python
# better_arg.py

parser = argparse.ArgumentParser(description='读取文件并统计行数')
args = parser.parse_args()
with open(args.filename, 'r', encoding='utf-8') as f:
    if args.lines:
        print(sum(1 for _ in f))
    else:
        print(f.read())
```

#### 注意事项/最佳实践
- 使用 `argparse` 提供良好的命令行界面与帮助信息（`-h/--help`）。
- 验证用户输入并给出清晰错误信息。

#### 权衡与替代
- 对于短小脚本 `sys.argv` 足够；对公开工具或复杂选项使用 `argparse` 或第三方库（如 `click`）。

#### 小结
命令行参数使脚本更灵活，选择合适的解析工具能提升用户体验与脚本可维护性。

## 最佳实践（速查）
- 总是使用 `with open(..., encoding='utf-8')` 来打开文本文件。
- 处理 CSV 时使用 `csv` 模块并指定 `newline=''`。
- 对可能失败的 IO 操作使用精确的 `try/except` 捕获并记录异常。
- 避免 `read()` 加载超大文件到内存，使用逐行或分块读取。
- 写入前考虑写到临时文件，然后原子替换以防止意外数据丢失。
- 使用 `argparse` 构建健壮的命令行接口。
