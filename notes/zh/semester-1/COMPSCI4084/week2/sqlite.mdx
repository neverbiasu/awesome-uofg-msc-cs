## 关键知识点

### 1. 关系型数据库与表设计

#### 动机
- 当数据存在重复值（比如多名学生修同一门课）时，把相关信息拆分到不同表并通过键关联能避免数据冗余并保持一致性。

#### 核心概念
- **表（Table）**：由列（字段）和行（记录）组成。
- **主键（Primary Key）**：唯一标识一条记录，通常用于快速索引与关联其他表。
- **数据类型**：`INTEGER`, `REAL`, `TEXT`, `BLOB` 等。
- **约束（NOT NULL, UNIQUE, PRIMARY KEY）** 保证数据完整性。

#### 使用场景/模式
- 将重复信息拆到单独的表（例如 `students` 与 `class`），并通过外键或 JOIN 连接。

#### 示例

```sql
-- students 表结构示例
CREATE TABLE IF NOT EXISTS students (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    class TEXT NOT NULL,
    grade INTEGER
);

-- class 表结构示例
CREATE TABLE IF NOT EXISTS class (
    class TEXT PRIMARY KEY,
    lecturer TEXT
);
```

#### 注意事项/最佳实践
- 为每张表选择合适的主键（自动增长整数通常是好选择）。
- 明确列的数据类型和是否允许为空（NOT NULL）。
- 如果多个表频繁联合查询，考虑是否需建立索引以提升查询性能。

#### 小结
良好的表设计是数据库性能与维护性的基础，主键与约束有助于保证数据一致性。

### 2. 在 Python 中使用 sqlite3：连接与游标

#### 动机
- 需要在本地以轻量方式持久化数据而无需部署数据库服务器时，SQLite 是理想选择；Python 标准库内置 `sqlite3`，上手快。

#### 核心概念
- `sqlite3.connect('dbfile.db')` 返回连接对象（Connection）。
- `conn.cursor()` 返回游标（Cursor），用于执行 SQL 语句与获取结果。
- 使用 `with sqlite3.connect(...) as conn:` 可以在上下文退出时自动提交或回滚事务。

#### 使用场景/模式
- 小型应用、教学示例、开发原型、工具脚本中的数据持久化。

#### 示例

```python
import sqlite3

with sqlite3.connect('company.db') as conn:
    cursor = conn.cursor()
    cursor.execute('SELECT sqlite_version()')
    print(cursor.fetchone())
```

#### 注意事项/最佳实践
- 若使用 `with` 包装连接，事务会在退出时自动提交（如未发生异常），发生异常则回滚。
- 关闭连接：`conn.close()`（使用 `with` 时自动关闭）。

#### 小结
`sqlite3` 提供简单的连接与游标接口，用 `with` 管理事务和连接是推荐做法。

### 3. CRUD：创建、插入、查询、更新、删除

#### 动机
- 数据库的核心工作是对表中数据进行增删改查（CRUD）。掌握这些 SQL 语句及在 Python 中如何执行是日常使用的基础。

#### 核心概念
- `CREATE TABLE`, `INSERT INTO`, `SELECT`, `UPDATE`, `DELETE`。
- `cursor.execute()` 执行 SQL，`conn.commit()` 保存更改（当使用 `with` 时通常自动 commit）。

#### 使用场景/模式
- 初始化数据库并插入种子数据；查询特定记录；更新用户信息；删除过期记录等。

#### 示例

```python
# 创建表（一次性）
cursor.execute('''
CREATE TABLE IF NOT EXISTS students(
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    class TEXT NOT NULL,
    grade INTEGER
)
''')

# 插入（参数化示例见下节）
cursor.execute('INSERT INTO students (id, name, class, grade) VALUES (1, "Mary", "Python", 67)')
conn.commit()

# 查询
cursor.execute('SELECT id, name, grade FROM students')
for row in cursor.fetchall():
    print(row)

# 更新
cursor.execute('UPDATE students SET name = ? WHERE id = ?', ("Richard", 1))
conn.commit()

# 删除
cursor.execute('DELETE FROM students WHERE id = ?', (1,))
conn.commit()
```

#### 注意事项/最佳实践
- 对于多次插入，使用 `executemany()` 或批量事务可以显著提升性能。
- 避免在字符串格式化的 SQL 中直接插入用户输入（见参数化查询）。

#### 小结
熟练使用 CRUD 语句并结合事务管理能实现可靠的数据操作流程。

### 4. 参数化查询与防注入

#### 动机
- 直接把用户输入拼接到 SQL 语句会引发 SQL 注入风险，参数化查询可以安全地把用户输入作为参数传递。

#### 核心概念
- 使用 `?` 占位符（或命名参数 `:name`）把值传给 `cursor.execute(sql, params)`，由驱动安全地处理转义。

#### 使用场景/模式
- 接收用户输入（如通过 `input()`、命令行或 web API），并基于它们执行查询或更新操作。

#### 示例

```python
which_class = input('Enter a class: ')
cursor.execute('SELECT * FROM students WHERE class = ?', (which_class,))
rows = cursor.fetchall()
for row in rows:
    print(row)
```

#### 注意事项/最佳实践
- 参数必须作为元组或序列传给 `execute()`（例如 `(which_class,)`）。
- 不要用 Python 字符串拼接或格式化来构造包含用户输入的 SQL。

#### 小结
参数化查询是防止 SQL 注入的最简单有效方法，务必养成习惯。

### 5. 事务管理：commit 与 rollback

#### 动机
- 一组相关的数据库操作应作为一个原子事务，当其中任一步骤失败时应回滚以避免数据不一致。

#### 核心概念
- `conn.commit()` 提交事务，`conn.rollback()` 回滚未提交的更改。
- 使用 `with sqlite3.connect(...) as conn:` 在退出时自动提交或回滚（若发生异常）。

#### 使用场景/模式
- 转账操作（必须保证借方与贷方同时更新成功或全部回滚）。
- 批量插入：全部插入成功才 commit，失败则 rollback。

#### 示例

```python
try:
    with sqlite3.connect('company.db') as conn:
        cur = conn.cursor()
        cur.execute('UPDATE accounts SET balance = balance - ? WHERE id = ?', (100, 1))
        cur.execute('UPDATE accounts SET balance = balance + ? WHERE id = ?', (100, 2))
        # 若任一语句失败，with 块外的异常会触发回滚
except Exception as e:
    print('事务失败，已回滚：', e)
```

#### 注意事项/最佳实践
- 在需要保持强一致性的操作中，将多条语句包裹在同一事务中。
- 不要在长时间事务中持有连接（会阻塞其他操作）；尽量缩短事务范围。

#### 小结
事务保证了一系列数据库操作的原子性，合理使用 commit/rollback 是数据库编程的基础。

### 6. 联表查询（JOIN）与数据抽取

#### 动机
- 数据通常拆分在多张表中，必须通过 JOIN 将它们组合以得到完整信息（例如学生姓名与其班级讲师）。

#### 核心概念
- 常见 JOIN：`INNER JOIN`（仅匹配的行）、`LEFT JOIN`（左表全部行 + 右表匹配行）等。SQLite 支持标准的 SQL JOIN 语法。

#### 使用场景/模式
- 查询学生及其班级讲师信息时，将 `students` 与 `class` 表用共享字段 `class` 关联。

#### 示例

```sql
SELECT students.id, students.name, class.lecturer
FROM students
JOIN class ON students.class = class.class
WHERE students.grade > 70;
```

#### 注意事项/最佳实践
- 在 JOIN 大表时注意性能，考虑为连接字段建立索引。
- 确保 JOIN 条件正确（避免笛卡尔积）。

#### 小结
JOIN 是关系型数据库的强大特性，用于从多表组合与抽取所需信息。

### 7. 常见错误与调试技巧

#### 动机
- 新手常因 SQL 语法、错别字段名、事务未提交或连接未关闭导致问题。掌握调试技巧能更快定位问题。

#### 核心概念
- 常见错误：拼写错误、使用未创建的表、忘记 commit（导致看不到更改）、未参数化查询导致注入风险。
- 使用 `cursor.lastrowid` 获取最近插入记录的主键；使用 `cursor.rowcount` 检查受影响行数（SQLite 对 `rowcount` 支持有限）。

#### 示例

```python
# 插入后获取自动生成的 id
cur.execute('INSERT INTO students (name, class, grade) VALUES (?, ?, ?)', ('Alice', 'Python', 85))
print('New id:', cur.lastrowid)
conn.commit()

# 查询并打印错误上下文
try:
    cur.execute('SELECT * FROM non_existing_table')
except sqlite3.OperationalError as e:
    print('SQL 错误:', e)
```

#### 注意事项/最佳实践
- 在开发时开启详细日志或打印 SQL 语句有助于排查问题。
- 使用事务和单元测试验证重要的数据变更逻辑。

#### 小结
通过打印错误信息、记录 SQL 及合理使用事务可以显著提高调试效率并减少生产事故。

## 最佳实践（速查）

- 使用参数化查询（`?`）避免 SQL 注入。
- 使用 `with sqlite3.connect(...) as conn:` 管理事务并确保连接关闭。
- 对频繁查询的列建立索引以提升性能。
- 使用 `executemany()` 批量插入以提升性能。
- 在修改重要数据前在测试数据库验证 SQL 逻辑。
