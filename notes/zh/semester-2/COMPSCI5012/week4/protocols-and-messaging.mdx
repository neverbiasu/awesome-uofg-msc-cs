## 核心要点
HTTP 是 Web 的基础协议，其无状态特性要求必须使用 Cookie 和 Session 等机制来跨请求维护应用程序状态。

## HTTP：基础
HTTP (超文本传输协议) 是客户端-服务器模型中的一种请求-响应协议。

### HTTP 特性
-   **无状态 (Stateless)**：每个请求都是独立的。服务器不“记得”之前的交互。
-   **基于 TCP/IP**：确保数据的可靠传输。
-   **方法**：`GET` (检索), `POST` (提交), `PUT` (更新), `DELETE` (删除)。

## 无状态性与状态管理
由于 HTTP 是无状态的，Web 应用程序使用变通方法来跟踪用户。

### 状态管理技术
-   **Cookie**：存储在客户端（浏览器）上的小数据片段。
-   **Session (会话)**：服务器端存储，映射到会话 ID（通常存储在 Cookie 中）。
-   **URL 重写**：在 URL 中嵌入状态（安全性较低）。
<Callout type="warn">
**安全细微差别**：传输敏感状态信息时必须使用 HTTPS (HTTP over TLS/SSL)，以防止窃听和中间人 (MitM) 攻击。
</Callout>

## Web 消息传递协议
除了标准 HTTP 外，其他协议也支持实时或结构化通信。
-   **WebSockets**：在单个 TCP 连接上进行全双工通信通道。
-   **REST (表述性状态转移)**：一种使用标准 HTTP 方法的网络应用程序架构风格。

## 出卷人视角：技术细微差别

### 持久连接 vs. 非持久连接
-   **非持久**：每个对象一个连接（先 HTML，再图像 1，再图像 2）。开销大。
-   **持久 (HTTP/1.1+)**：可以通过单个连接发送多个对象。速度快得多。

### 必记的状态码
-   `200 OK`：成功。
-   `301/302`：重定向。
-   `403 Forbidden` / `404 Not Found`：客户端错误。
-   `500 Internal Server Error`：服务器错误。
