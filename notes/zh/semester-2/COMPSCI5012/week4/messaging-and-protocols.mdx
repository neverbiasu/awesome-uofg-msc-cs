## 1. 网络通信模型

### OSI 模型 (7 层)
1.  **物理层 (Physical)**：二进制传输（电缆、信号）。
2.  **数据链路层 (Data Link)**：MAC 地址寻址（帧）。
3.  **网络层 (Network)**：IP 地址寻址和路由（数据包）。
4.  **传输层 (Transport)**：端到端可靠性（TCP/UDP 段）。
5.  **会话层 (Session)**：通信维护。
6.  **表示层 (Presentation)**：加密、压缩（如 SSL/TLS）。
7.  **应用层 (Application)**：网络进程到应用（HTTP, FTP, DNS）。

### TCP/IP 模型 (4 层)
1.  **链路/物理层 (Link/Physical)**：通过物理网络传输。
2.  **互联网层 (Internet)**：IP 地址寻址和路由。
3.  **传输层 (Transport)**：TCP（可靠）/ UDP（不可靠）。
4.  **应用层 (Application)**：HTTP, DNS, SMTP。

## 2. HTTP 基础

**HTTP (超文本传输协议)** 是一种用于在 Web 上传输资源（HTML、图像、JSON）的请求-响应协议。

### 请求-响应模式
1.  **客户端**发送请求（方法、URL、标头、主体）。
2.  **服务器**发送响应（状态码、标头、主体）。

![请求流](/images/COMPSCI5012/week4/L4-ProtocolsMessagingCoursework-013.png)

### HTTP 方法

| 方法 | 描述 | 特性 |
| :--- | :--- | :--- |
| **GET** | 获取数据 | 安全、幂等、可缓存、数据在 URL 中 |
| **POST** | 提交数据 | 不安全、不幂等、数据在主体中 |
| **PUT** | 更新/创建资源 | 幂等 |
| **DELETE** | 删除资源 | 幂等 |

<Callout title="GET vs POST">
- **GET**：参数在 URL 中可见，长度受限，可添加书签/缓存。用于获取数据。
- **POST**：参数在主体中，无长度限制，不被缓存。用于敏感数据或状态更改。
</Callout>

### 无状态性
HTTP 是无状态的：服务器在请求之间不保留关于客户端的信息。
**解决方案**：
- **Cookies**：在客户端存储会话 ID。
- **Sessions**：在服务器端存储用户状态。

### 持久连接
- **HTTP 1.0**：每个请求都建立新连接（慢）。
- **HTTP/2**：多路复用（通过一个连接并行处理多个请求）。
- **HTTP/3**：使用 QUIC（基于 UDP）以实现更低延迟。

## 4. 进程间通信 (IPC)

用于分布式系统通信的协议。

### 传统协议
- **XML-RPC**：通过 HTTP 使用 XML 的远程过程调用。
- **SOAP (简单对象访问协议)**：严格、冗长的基于 XML 的协议。复杂但具有稳健的安全/事务支持。

### 现代协议
- **gRPC**：
    - Google 开发的现代开源 RPC 框架。
    - 使用 **HTTP/2** 和 **Protocol Buffers**（二进制格式）。
    - 高性能，支持流处理。
- **REST (具象状态传输)**：
    - 一种架构风格，而非严格协议。
    - 使用标准 HTTP 方法（GET, POST, PUT, DELETE）。
    - 无状态且可缓存。
    - 通常使用 **JSON** 进行数据交换。
