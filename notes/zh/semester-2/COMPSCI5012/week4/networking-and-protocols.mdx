## 概要

- **目标**：理解 Web 应用作为网络应用的基础，掌握 HTTP 协议的工作原理，区分 GET 和 POST 请求，并深入了解进程间通信（IPC）协议，特别是 REST。
- **范围**：网络模型 (OSI/TCP-IP)、HTTP 请求/响应生命周期、HTTP 方法、无状态性与解决方案（Cookies）、REST 与 gRPC。

## 学习目标

1. **解释** 网络通信的基本原理（分层架构）。
2. **掌握** HTTP 协议及其关键特性（无状态、请求/响应模式）。
3. **区分** HTTP GET 和 POST 方法的使用场景与安全性。
4. **理解** 进程间通信 (IPC)，特别是 RESTful API 的设计理念。

## 关键知识点

### 1. Web 应用即网络应用

- **核心概念**：
  - **客户端 (Client)**：间歇性连接，向服务器请求资源，不与其他客户端直接通信。
  - **服务器 (Server)**：始终在线，通常位于数据中心，负责响应请求。
- **网络模型**：
  - **OSI 模型 (7层)**：Application, Presentation, Session, Transport, Network, Data Link, Physical。
  - **TCP/IP 模型 (4层)**：
    - **应用层 (Application)**：HTTP/HTTPS (Web), DNS (域名解析), SMTP (邮件)。
    - **传输层 (Transport)**：TCP (可靠传输), UDP (不可靠传输)。
    - **网络层 (Internet)**：IP (寻址与路由)。
    - **链路层 (Link)**：物理传输。

### 2. HTTP 协议 (Hypertext Transfer Protocol)

- **定义**：用于在 Web 上传输超媒体文档（如 HTML）的应用层协议。
- **模式**：请求-响应 (Request-Response) 模式。
- **无状态性 (Stateless)**：服务器不保存客户端的任何状态信息。每次请求都是独立的。
  - **问题**：无法维持登录状态、购物车等。
  - **解决方案**：
    - **Client-side**: Cookies, URL 重写 (Session ID)。
    - **Server-side**: Sessions, 隐藏表单域。

### 3. HTTP 方法：GET vs POST

| 特性 | GET | POST |
| :--- | :--- | :--- |
| **用途** | 获取数据 (Retrieve) | 提交数据 (Submit/Update) |
| **数据位置** | URL 查询字符串 (Query String) | 消息体 (Message Body) |
| **可见性** | URL 中可见 (不安全) | URL 中不可见 (相对安全) |
| **长度限制** | 有限制 (约 2048 字符) | 无限制 |
| **缓存/书签** | 可缓存，可收藏书签 | 不可缓存，不可收藏 |
| **幂等性** | 是 (Idempotent) | 否 |
| **副作用** | 无 (Safe) | 有 (Side effects) |

### 4. 进程间通信 (IPC)

当应用分布在不同机器上时（如微服务、云架构），需要 IPC 协议：

- **Legacy**: SOAP (复杂, XML), XML-RPC。
- **Modern**:
  - **gRPC**: 基于 HTTP/2，高性能，使用 Protocol Buffers，强类型。适合微服务内部通信。
  - **REST (Representational State Transfer)**:
    - **风格**：利用 HTTP 标准方法 (GET, POST, PUT, DELETE) 操作资源。
    - **格式**：通常使用 JSON 或 XML。
    - **特点**：轻量、无状态、可伸缩。是 Web API 的主流标准。

## 最佳实践

- **使用正确的 HTTP 方法**：不要用 GET 来提交敏感数据（如密码）或执行有副作用的操作（如删除）。
- **优化性能与可持续性**：
  - **持久连接 (Persistent HTTP)**：复用 TCP 连接，减少握手开销 (HTTP/1.1+)。
  - **浏览器缓存**：利用 HTTP 缓存头 (`Cache-Control`, `ETag`) 减少不必要的数据传输。
  - **压缩**：压缩传输的文件 (Gzip, Brotli)。
- **RESTful 设计**：设计 API 时，URL 应代表资源（名词），HTTP 方法代表操作（动词）。
