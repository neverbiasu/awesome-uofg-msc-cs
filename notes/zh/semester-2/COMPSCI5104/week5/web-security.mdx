## 核心要点
Web 安全是一场针对注入攻击和损坏的访问控制的持久战。开发人员必须超越简单的输入过滤，采用 CSRF 令牌和内容安全策略 (CSP) 等健壮的、框架级别的保护措施。

## 1. OWASP Top 10
开放 Web 应用程序安全项目 (OWASP) 维护着一份最关键的 Web 安全风险列表。
1.  **损坏的访问控制**：用户访问了他们不应该访问的资源（例如：通过更改 URL 中的 ID 来查看他人的个人资料）。
2.  **加密失败**：使用弱算法或暴露敏感数据的明文。
3.  **注入**：SQL 注入、XSS 和操作系统命令注入。

## 2. 损坏的访问控制 (Broken Access Control)
-   **不安全的直接对象引用 (IDOR)**：攻击者通过更改参数值（例如：`user_id=123` $\rightarrow$ `user_id=124`）来绕过授权。
-   **缓解措施**：始终在服务器端执行检查，以确保登录用户确实拥有所请求资源的所有权。

## 3. 请求伪造攻击

### 跨站请求伪造 (CSRF)
攻击者诱导受害者的浏览器向受害者已登录的易受攻击的 Web 应用发送伪造请求。
-   **防御**：**CSRF 令牌**。对于改变状态的请求（POST/PUT），要求提供一个唯一的、秘密的且不可预测的令牌。

### 跨站脚本攻击 (XSS) - 重访
-   **内容安全策略 (CSP)**：一种浏览器端的安全层，告诉浏览器哪些脚本源是可信的，从而有效地禁用大多数 XSS 攻击。

## 4. 出卷人视角：技术细微差别

### 认证 (Authentication) vs. 授权 (Authorization)
-   **认证**：证明你是谁（例如：登录）。
-   **授权**：证明你被允许做什么（例如：权限）。
- *考试技巧*：一个系统即使有完美的认证，如果它不检查每个敏感操作的授权，仍然会失败。

### 安全 Cookie
-   **HttpOnly**：防止 JavaScript (XSS) 读取 Cookie。
-   **Secure**：确保 Cookie 仅通过 HTTPS 发送。
-   **SameSite**：通过限制 Cookie 何时随跨站请求发送来缓解 CSRF。
