## 核心要点
移动安全依赖于强大的操作系统级隔离（沙箱）和权限机制，但如果开发人员没有正确实现特定平台的安全 API，则仍然容易受到不安全数据存储和通信的影响。

## 1. 移动平台架构
移动操作系统采用比传统桌面更严格的模型。
-   **沙箱 (Sandboxing)**：每个应用都在自己受限的环境中运行（唯一的 User ID）。它不能访问其他应用的文件。
-   **权限**：应用必须显式请求访问敏感资源（摄像头、联系人）。
![Android 沙箱模型](/images/COMPSCI5104/week6/SSE-Lecture6-010.png)

## 2. 常见的移动端漏洞
-   **不安全的数据存储**：将敏感数据以明文形式存储在 SharedPreferences (Android) 或 Plist (iOS) 文件中。
-   **损坏的加密**：实现自定义加密或在源代码中硬编码密钥。
-   **不安全的通信**：未能验证 SSL/TLS 证书（存在中间人攻击风险）。

## 3. 逆向工程与保护
移动应用很容易被反编译（例如：使用 JADX）。
-   **混淆 (Obfuscation)**：将变量/方法名改为无意义的字符串，使代码难以阅读。
-   **篡改检测**：检查应用是否被修改或是否运行在已 root/越狱设备上的代码。

## 4. 出卷人视角：技术细微差别

### Root/越狱
-   **细微差别**：Root 会破坏操作系统级的沙箱。如果应用在已 Root 的设备上运行，其敏感数据将不再受操作系统保护，无法防御其他恶意应用。
- *考试技巧*：高安全性应用（如银行应用）应检测 Root 并拒绝运行。

### Intent 注入 (Android)
-   **概念**：攻击者可以向导出的应用组件发送恶意 "Intent"，以代表该应用执行操作。
-   **缓解措施**：除非必要，不要导出组件；使用显式 Intent。
