## 概要

- **目标**：理解 Apache Spark 的运行时架构及其核心组件，掌握作业从提交到执行的完整流程。
- **范围**：涵盖 Spark Compute 组件（Driver, Master, Worker, Executor）、执行阶段（DAG, Stage, Task）以及与 Hadoop 的对比。

## 学习目标

1. **识别** 并描述 Spark 的核心组件（Client, Driver, Master, Worker, Executor）及其职责。
2. **解释** Spark 的执行阶段，包括 DAG 的构建、Stage 的划分以及 Task 的调度。
3. **理解** Spark 作业的生命周期，从 `SparkContext` 初始化到任务执行及结果返回。
4. **对比** Spark 与 Hadoop 在架构上的关键差异（如内存计算、Driver 生命周期）。

## 关键知识点

### 1. Spark 计算架构 (Spark Compute)

Spark 的运行时架构由多个协同工作的组件组成：

- **Client (客户端)**：
  - 用户提交作业的软件环境。
  - 负责与 Spark Master 通信以提交作业。
- **Driver (驱动器)**：
  - 执行 Spark 作业的**主程序**（包含 `main` 函数）。
  - 可以运行在 Client 节点上，也可以运行在集群节点上。
  - 负责创建 `SparkContext`，解析代码，生成 DAG，并将任务分发给 Executor。
- **Spark Master (主节点)**：
  - 资源管理器。接收 Client 的作业提交，分析 DAG，分配资源，并与 Driver 通信。
  - 负责管理集群中的 Worker 节点。
- **Spark Worker (工作节点)**：
  - 管理节点上的本地资源（CPU, RAM）。
  - 负责启动和监控 Executor 进程。
- **Executor (执行器)**：
  - 运行在 Worker 节点上的 JVM 进程。
  - 负责执行具体的 Task，并将数据存储在内存或磁盘中。
  - 使用线程池（ThreadPool）并发执行多个 Task。

### 2. Spark 执行阶段 (Execution Phases)

Spark 的执行过程是惰性（Lazy）且分阶段的：

1.  **初始化**：Client 实例化 `SparkContext` (SC)。SC 负责与集群管理器交互并初始化 Driver。
2.  **RDD 创建**：使用 SC 创建输入 RDD（通常跨节点分区）。
3.  **Transformations (转换)**：对 RDD 应用转换操作（如 `map`, `filter`）。此时**不执行**任何计算，仅记录转换序列（Lineage）形成 DAG（有向无环图）。
4.  **Action (动作)**：Client 调用 Action（如 `count`, `collect`）触发实际计算。
5.  **DAG 构建**：Driver 中的 `DAGScheduler` 将 DAG 划分为多个 **Stage**（阶段）。
    - Stage 的划分依据是 Shuffle 依赖（宽依赖）。
6.  **任务调度**：`DAGScheduler` 将 Stage 提交给 `TaskScheduler`。
7.  **任务执行**：`TaskScheduler` 将 **Task**（任务）分发给 Executor 执行。
    - 监控执行进度，处理失败重试（Stragglers）。
    - Executor 执行完毕后将结果返回给 Driver。

### 3. 作业执行剖析 (Job Execution Anatomy)

一个典型的 Spark 作业执行流程如下：

1.  **启动程序**：运行 Spark 程序，启动 JVM。
2.  **创建上下文**：初始化 `SparkContext`。
3.  **初始化 Driver**：启动 Driver 程序，注册到 Spark Master / Cluster Manager。
4.  **请求资源**：Master 指示 Worker 为应用分配资源。
5.  **启动 Executor**：Worker 启动 Executor 进程（每个作业有独立的 Executor）。
6.  **加载数据 & 创建 RDD**：Driver 定义 RDD 及其依赖关系。
7.  **构建 DAG (Lazy)**：执行 Transformations，逐步构建 DAG，但不立即计算。
8.  **触发 Action**：遇到 Action 操作，DAG 被发送给 `DAGScheduler`。
9.  **划分 Stage**：`DAGScheduler` 根据宽依赖拆分 Stage。
10. **分发 Task**：`TaskScheduler` 将 Task 发送到 Executor。
11. **执行 Task**：Executor 并行执行 Task，处理数据分区。
12. **结果返回**：Task 完成，结果返回给 Driver 或写入存储。
13. **作业完成**：所有 Stage 完成，Driver 退出，释放资源。

### 4. Spark 与 Hadoop 的重要区别

- **存储层**：Spark 没有内置的持久化存储层（依赖 HDFS, S3 等），但支持内存缓存。
- **Driver 生命周期**：Spark Driver 必须在作业运行期间一直保持在线（它是 Action 的接收者）。
- **Executor 隔离**：每个 Spark Job 在 Worker 上有独立的 Executor，避免作业间内存共享冲突。
- **启动速度**：Spark 启动和任务调度通常比 Hadoop MapReduce 更快（线程级 vs 进程级）。

## 最佳实践

- **理解惰性求值**：利用 Spark 的 Lazy 特性，避免不必要的中间计算。
- **合理划分 Stage**：减少宽依赖（Shuffle）可以减少 Stage 数量，提升性能。
- **资源管理**：根据作业规模合理配置 Executor 的内存和核心数。
